## 1. 한 줄 요약

작업 영역을 2D 격자로 보고, 로봇이 (0,0)에서 출발해 **장애물을 제외한 모든 격자 셀을 한 번씩 방문하는 커버리지 경로**를 생성하는 PPO(CNN) 정책이다. 각 셀은 결속 지점이다. 결속(TIE) 동작은 모델이 출력하지 않는다. 모델은 **이동 방향만** 출력하고, 셀에 도착하면 그 셀은 결속된 것으로 간주한다. 실제 결속 동작은 상위 제어기가 담당한다.

## 3. 문제 정의 (MDP)

### 3.1 좌표계 / 물리 단위

| 항목 | 격자 | 실제 |
|---|---|---|
| X축 = **열(col)** | 1칸 | **600 mm** (무한궤도 전진/후진, 빠름) |
| Y축 = **행(row)** | 1칸 | **400 mm** (횡이동, 느림) |
| 위치 표기 | `(col, row)` 튜플 | `x = min_x + col·600`, `y = min_y + row·400` |
| 시작점 | 항상 `(0, 0)` | `work_area`의 `(min_x, min_y)` |

> ⚠️ 코드 전반에서 **좌표는 `(col, row)` 순서**이고, numpy 배열 인덱싱은 `[row, col]` 순서다. 혼동하기 쉬우니 주의.

### 3.2 행동 공간 — `Discrete(4)`

| id | 이름 | 이동 |
|---|---|---|
| 0 | `MOVE_X_POS` | col + 1 (전진 600 mm) |
| 1 | `MOVE_X_NEG` | col − 1 (후진 600 mm) |
| 2 | `MOVE_Y_POS` | row + 1 (횡이동 +400 mm) |
| 3 | `MOVE_Y_NEG` | row − 1 (횡이동 −400 mm) |

- 경계 밖이나 장애물 셀로 이동하려 하면 **제자리에 머물고** 페널티를 받는다. 경로에는 추가되지 않는다.

### 3.3 관측 (입력)

**① 격자 텐서 `(8, 32, 32)` float32**: 가변 크기 격자를 32×32로 보간한다(`state_encoder.grid_to_cnn_input`).

| ch | 의미 | 보간 |
|---|---|---|
| 0 | 로봇 위치 (one-hot) | nearest |
| 1 | 방문 셀 | nearest |
| 2 | frontier (방문 셀과 인접한 미방문 유효 셀) | nearest |
| 3 | 장애물 | nearest |
| 4 | 유효 영역 (장애물이 아닌 셀) | nearest |
| 5 | 미방문 셀까지 BFS 거리 (0~1 정규화) | bilinear |
| 6 | x 위치 그래디언트 (col/(cols−1)) | bilinear |
| 7 | y 위치 그래디언트 (row/(rows−1)) | bilinear |

**② 보조 벡터 `(4,)` float32**: `env.get_aux_input()`
`[coverage_ratio, step_ratio(=step/max_steps), x_progress, y_progress]`

### 3.4 보상 함수 (8차 기준, 추론 시에는 사용하지 않음)

| 이벤트 | 보상 |
|---|---|
| X 이동 비용 | −0.5 |
| Y 이동 비용 | **−2.0** (7차는 −1.0이었고, 8차에서 횡이동을 줄이려고 올림) |
| 새 셀 방문 | 이동비용 + 3.0 + (1/유효셀수)×50 |
| 재방문 | 이동비용 − 1.5 |
| 경계/장애물 충돌 | −5.0 |
| 스텝 페널티 | −0.05 / step |
| 커버리지 25/50/75% 마일스톤 | +10 / +20 / +30 |
| 전체 커버 완료 | +100 (에피소드 종료) |

- **종료 조건**: 모든 유효 셀 방문 시 `terminated`, `max_steps = rows × cols × 3` 도달 시 `truncated`

## 4. 모델 구조 / 학습 방법

### 4.1 네트워크 (`agents_cnn.py`)

```
grid (8,32,32)
 → Conv3x3(32)+BN+ReLU+MaxPool → Conv3x3(64)+BN+ReLU+MaxPool → Conv3x3(128)+BN+ReLU+AdaptiveAvgPool(4x4)
 → flatten(2048) ⊕ aux(4) = 2052
 → FC 256 + ReLU + Dropout(0.1) → FC 128 + ReLU
 → policy_head: Linear(128→4) (logits)
 → value_head : Linear(128→1)
```

### 4.2 알고리즘 / 하이퍼파라미터

| 항목 | 값 |
|---|---|
| 알고리즘 | PPO (clip 0.2) + GAE (γ=0.99, λ=0.95) |
| 롤아웃 길이 | 256 step마다 업데이트, epoch 4, minibatch 64 |
| 학습률 | 3e-4 → 5e-5 선형 감쇠 |
| entropy 계수 | 0.02 → 0.005 선형 감쇠 |
| value 계수 / grad clip | 0.5 / 0.5 |
| 보상 스케일 | 버퍼 저장 시 ×0.1 (value 학습 안정화) |
| 총 에피소드 | 300,000 예정, **97,000에서 조기종료** (약 1.3시간) |
| 조기종료 조건 | 최근 500ep 평균보상 > 0, 평가 CR > 0.95, 10개 테스트 그리드 각각 CR > 0.90 |

### 4.3 성취 기반 커리큘럼 (5단계)

| Phase | rows | cols | 장애물 수 | 졸업 기준 CR | 8차 진입 시점 |
|---|---|---|---|---|---|
| 1 | 2~3 | 2~4 | 0 | 0.85 | ep 0 |
| 2 | 2~4 | 2~6 | 0 | 0.80 | ep 8,000 |
| 3 | 3~5 | 3~8 | 0~1 | 0.75 | ep 18,000 |
| 4 | 4~6 | 4~10 | 1~3 | 0.60 | ep 33,500 |
| 5 | 4~6 | 3~15 | 0~5 | (최종) | ep 49,000 |

- 각 단계는 최소 에피소드 수를 채우고, 해당 단계 전용 평가 그리드에서 졸업 기준 CR을 넘어야 다음 단계로 넘어간다.
- 이전 단계 그리드를 30~45% 확률로 다시 섞어 망각을 방지한다(replay).
- Phase 4 안에는 서브 커리큘럼이 있다. 처음 20k는 소형, 다음 30k는 중형, 그 뒤로 전체 범위를 사용한다.
- 장애물은 매 에피소드 무작위 단일 셀이며, 시작점 (0,0)은 제외한다.

## 5. 성능 (10개 고정 테스트 그리드, greedy 추론)

> 추론은 `argmax`이고 eval 모드(Dropout 꺼짐, BN 고정)라 **결정론적**이다. 같은 입력이면 항상 같은 경로가 나온다.
> CR = 완료율(방문한 유효 셀 / 전체 유효 셀), PE = 경로 효율(실제 스텝 / (유효셀 + rows − 1), 낮을수록 좋음), YR = 전체 이동 중 Y 이동 비율.

### 5.1 그리드별 결과 (2026-10-17 재측정)

| 그리드 | 8th **best** CR / PE / YR | 8th final CR / PE / YR | 7th best (기존 배포) CR / PE / YR |
|---|---|---|---|
| 2×3 | 1.000 / 0.71 / 0.20 | 1.000 / 0.71 / 0.20 | 1.000 / 0.71 / 0.40 |
| 3×5 | 1.000 / 0.82 / 0.21 | 1.000 / 0.82 / 0.21 | 1.000 / 0.82 / 0.36 |
| 4×5 | 1.000 / 0.83 / 0.32 | 1.000 / 0.83 / 0.32 | 1.000 / 0.83 / 0.47 |
| 4×5 + 장애물1 | 1.000 / 0.82 / 0.39 | 1.000 / 0.82 / 0.39 | 1.000 / 0.82 / 0.50 |
| 5×8 | 1.000 / 0.89 / 0.26 | 1.000 / 0.89 / 0.26 | 1.000 / 0.89 / 0.36 |
| 5×8 + 장애물2 | 1.000 / **2.62** / 0.75 | 1.000 / 0.90 / 0.32 | 1.000 / 1.02 / 0.30 |
| 6×10 | 1.000 / 0.91 / 0.24 | 1.000 / 0.91 / 0.24 | 1.000 / 0.91 / 0.34 |
| 6×10 + 장애물3 | 1.000 / 0.98 / 0.28 | 1.000 / 1.31 / 0.26 | 1.000 / 1.03 / 0.38 |
| 8×12 | 1.000 / 1.00 / 0.28 | 1.000 / 2.11 / 0.19 | 1.000 / 0.99 / 0.31 |
| 10×15 + 장애물4 | 0.986 / 2.90 / 0.50 | **0.747** / 2.90 / 0.61 | 0.986 / 2.90 / 0.52 |

(PE가 1보다 작은 값이 나오는 이유는 기준식 `유효셀 + rows − 1`이 시작 셀을 포함해 최소 스텝을 다소 과대 추정하기 때문이다. 그리드끼리 상대 비교하는 용도로만 보면 된다.)

### 5.2 해석

- **8th best는 7th와 완료율이 같고, 횡이동(YR)은 0.39에서 0.34로 줄었다.** 8차의 목적이었던 횡이동 억제는 부분적으로 달성했다. 목표치 YR < 0.25는 아직 미달이다.
- 다만 **5×8 + 장애물2** 그리드에서는 PE 2.62로 왕복 배회가 나타난다. 100% 커버는 하지만 경로가 약 2.6배 길다. 장애물 배치에 따라 이런 비효율 경로가 나올 수 있다.
- **10×15 + 장애물4**(가장 큰 그리드)는 세 모델 모두 `max_steps`(450 step)에서 잘린다. 98.6%를 커버하고 2개 셀을 남긴다. 학습한 행 범위(최대 6)를 넘는 크기라서 일반화에 한계가 있다.
- final 모델은 마지막 업데이트 한 번으로 대형 그리드 성능이 무너졌다. 그래서 **best 모델을 사용한다.**

## 7. 추론 사용법

### 7.1 최소 예제

```python
from agents_cnn import CNNPPOAgent
from environment_cnn import RebarGridCNNEnv

agent = CNNPPOAgent()                       # 기본값 n_channels=8 (반드시 8)
agent.load('cnn_ppo_agent_best.pth')        # CPU/GPU 자동 선택
env = RebarGridCNNEnv()

obs, _ = env.reset(grid_rows=5, grid_cols=8,
                   obstacles=[(1, 2), (4, 3)],   # (col, row)
                   start_pos=(0, 0))
done = False
while not done:
    aux = env.get_aux_input()
    action = agent.predict(obs, aux)        # greedy, 결정론적
    obs, _, terminated, truncated, info = env.step(action)
    done = terminated or truncated

path = env.extract_path()                   # [(col,row), ...] 시작점 포함
print(info['completion_rate'])
```

### 7.2 장비 연동용 래퍼: `path_generator.RLPathGenerator`

```python
gen = RLPathGenerator('cnn_ppo_agent_best.pth', algorithm='ppo')
waypoints = gen.generate(
    work_area={'min_x': 0, 'min_y': 0, 'max_x': 4800, 'max_y': 2000},  # mm
    obstacles_mm=[{'x': 1500, 'y': 800}],
)
# → [{'x': 0.0, 'y': 0.0}, {'x': 600.0, 'y': 0.0}, ...]  (mm, 이동 경로 전체)
```

- `grid_cols = ceil(폭 / 600)`, `grid_rows = ceil(높이 / 400)`
- 장애물 mm 좌표는 `int(x/600), int(y/400)` 셀로 변환된다.
- 기존 navigator의 `PATH_GEN` 커맨드용으로 `set_work_area()`와 `generate_from_command()`가 있다.

## 8. ⚠️ 주의사항 / 알려진 한계

1. **체크포인트의 `config.n_channels` 값이 7로 잘못 기록되어 있다.** 실제 모델은 **8채널**이다. config를 읽어서 네트워크를 만들면 로드에 실패하니, `CNNPPOAgent()`를 기본값(8)으로 생성할 것.
2. **추론 코드가 환경 코드에 의존한다.** 관측 생성(`state_encoder`)과 `get_aux_input`의 `step_ratio`가 `max_steps = rows·cols·3` 정의에 묶여 있다. 장비 쪽에서 관측을 새로 구현한다면 채널 순서, 보간 방식(채널 0~4는 nearest, 5~7은 bilinear, align_corners=False), aux 정의를 **정확히** 맞춰야 한다.
3. **경로 길이 상한**: 환경이 `rows·cols·3` 스텝에서 truncate한다. 그래서 `RLPathGenerator`의 `×6` 안전 여유는 실제로는 쓰이지 않는다. 완료율 < 1.0이면 미커버 셀이 남은 것이므로, 장비 측에서 **`info['completion_rate']`를 반드시 확인**하고, 남은 셀을 처리하는 후처리(예: BFS 최단경로로 잔여 셀 방문)를 두는 것을 권장한다.
4. **학습 분포 범위**: rows 2~6, cols 2~15, 장애물 0~5개(단일 셀), 시작점은 항상 (0,0)이다.
   - 이 범위를 벗어나는 큰 영역(예: rows ≥ 8)은 성능을 보장하지 않는다. 10×15에서 이미 98.6%다.
   - 32×32를 넘는 격자는 관측이 다운샘플링되어 셀 정보가 손실되므로 **사용 불가**다.
   - 큰 작업 영역은 여러 개의 소영역(예: ≤ 6×12)으로 나눠 순차 생성하는 방식을 권장한다.
   - 시작점이 (0,0)이 아닌 경우나 여러 셀을 차지하는 장애물은 학습하지 않았다.
5. **충돌 동작**: 모델이 벽이나 장애물 쪽 행동을 내면 환경은 제자리 유지로 처리하고 경로에 추가하지 않는다. 따라서 `extract_path()` 결과에는 유효한 이동만 남는다. 인접 웨이포인트는 항상 X 또는 Y로 정확히 1칸 차이다.
6. **경로에 재방문이 포함될 수 있다.** 재방문 셀에서 결속을 중복 수행하지 않도록, 상위 제어기에서 "처음 방문한 셀에서만 TIE"를 처리해야 한다.
7. **좌표 경계**: `ceil(폭/600)`개 열은 x = 0, 600, …, (cols−1)·600 위치다. 작업 영역 끝단(max_x)과 정확히 일치하지 않을 수 있으니, 실제 철근 간격과 격자 매핑은 장비 측에서 검증할 것.
8. **횡이동 비율**: YR 약 0.34. 목표 0.25에는 아직 못 미친다. 횡이동 비용이 큰 장비 특성상 추가 개선 여지가 있다.
