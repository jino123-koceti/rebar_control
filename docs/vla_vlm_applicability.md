# 철근결속 로봇 — VLA / VLM 적용 가능성 검토

> 작성일: 2026-08-03
> 대상: XYZ스테이지+결속건 상부체 + 무한궤도 주행부 자율 철근결속 로봇
> 결론 한 줄: **핵심 제어는 고전 CV/기하 유지, VLM은 "인지·감독 보조층"으로 선택 적용. VLA(end-to-end 액션)는 부적합.**

---

## 1. 용어 정리

| 약어 | 의미 | 입출력 | 예시 |
|------|------|--------|------|
| **VLM** | Vision-Language Model | 이미지+텍스트 → **텍스트/이해** | GPT-4V, Claude-vision, Qwen-VL, LLaVA, Grounding DINO, YOLO-World |
| **VLA** | Vision-Language-Action | 이미지+언어지시 → **로봇 액션(제어)** | RT-2, OpenVLA, Octo, π0(Physical Intelligence), RT-X |

- **VLM = "보고 이해/설명"**, **VLA = "보고 직접 움직임"**.

---

## 2. VLA (end-to-end 액션) — 이 로봇 핵심작업엔 부적합

RT-2/OpenVLA/π0류는 이미지+언어 → 로봇 액션을 직접 낸다. 우리 작업과 안 맞는 이유:

| 항목 | 문제 |
|------|------|
| **정밀도** | VLA는 보통 **cm급** 조작(집기/놓기/서랍)에 강함. 결속은 **mm급(<5mm) 위치정밀** 필요 → 미달 |
| **데이터** | VLA는 방대한 **로봇 시연 데이터** 필요. 커스텀 XYZ스테이지+결속건은 그런 데이터셋 없음, 수집도 비현실적 |
| **안전** | VLA는 확률적(가끔 엉뚱한 액션). **이미 폭주·프리즈 이력** 있는 로봇 제어경로에 예측불가 정책 = 위험. 산업작업은 결정적·검증가능 제어 필요 |
| **고전방식 우위** | 격자처럼 **구조화된 작업**은 YOLO검출+기하/캘리브가 더 정확·빠름·디버깅가능. VLA로 바꾸면 오히려 후퇴 |
| **연산** | 수십억 파라미터 → Jetson 실시간(제어 20Hz) 어려움 |

**→ 결속·주행 핵심 제어는 고전 CV/기하가 정답. VLA는 여기서 이득 없음.**

---

## 3. 왜 VLM이 (제한적으로) 더 적합한가

VLM은 **제어루프가 아니라 상위 "감독(supervisory)/인지" 층**에서 쓴다.

- **제어를 대체하지 않음** — 정밀 위치·모션은 그대로 기하/캘리브가 담당.
- **"이해가 필요한 곳"만 보강** — 좁은 학습모델이 못 보는 다양성·예상밖 상황.
- **저빈도(~1Hz) 감독** — 실시간 20Hz 제어와 분리 → 느려도 됨, 안전제어 경로 밖.
- **데이터 부담↓** — 오픈보캐뷸러리는 재학습·라벨링 없이 텍스트 프롬프트로 대상 지정.

즉 **"핵심 제어=고전, VLM=인지/감독 보조로 얹기"** 가 이 로봇에 맞는 구조.

## 4. VLM 적용 후보 (가치순)

| 용도 | 가치 | 설명 |
|------|------|------|
| **① 주행 장애물 오픈보캐뷸러리 검출** | ★★★ | 지금 obstacle_detector는 YOLO(사람 1클래스)만 → 공구·케이블·박스·잔해·장비·벽 등 **미지 장애물 다 놓침**. 오픈보캐뷸러리면 텍스트 프롬프트로 zero-shot 검출 → 주행안전 실질↑ |
| **② 결속 품질/이상 검사** | ★★ | "이 교차점 제대로 묶였나? 철근 휘었나/누락?" 좁은 YOLO가 못 잡는 이상 플래그 (결속 후 이미지 감독) |
| **③ 엣지케이스 의미이해** | ★ | 예상밖 배근/장면 semantic 판단, 실패 상황 설명·로깅 |
| **④ 자연어 작업지시/HRI** | ★ | "왼쪽 구역부터" 등 — 이미 자동화라 이득 제한적 |
| **정밀 위치제어** | ✗ | 절대 불가 — 기하/캘리브 몫 |

### 오픈보캐뷸러리(open-vocabulary) 검출이란
- **닫힌어휘(closed)**: 학습한 고정 클래스만 검출(현재 YOLO=사람). 새 물체 = 라벨링+재학습 필요.
- **열린어휘(open)**: 찾을 대상을 **텍스트로 지정**하면 학습 없이 검출. CLIP류가 "텍스트 뜻 ↔ 이미지 영역"을 매칭. 목록은 글자만 바꾸면 됨.
- 우리 주행 장애물처럼 **종류 다양·사전 라벨링 불가**한 상황에 적합.

## 5. 적용해볼 만한 VLM/모델

### 주행 장애물 검출 (실시간·엣지)
| 모델 | 특징 | 적합도 |
|------|------|--------|
| **YOLO-World** | YOLO+CLIP 텍스트임베딩. **실시간, Jetson 가능**. | ★★★ (주행 1순위) |
| **Grounding DINO** | 텍스트프롬프트 검출, 더 정확하나 무거움 | ★★ (저빈도 감독용) |
| **OWLv2 (OWL-ViT)** | 구글 오픈보캐뷸러리 | ★★ |
| **YOLOE / 최신 오픈보캐뷸러리 YOLO** | 실시간 오픈보캐뷸러리 계열 | ★★ |

### 세그멘테이션/영역 (오픈보캐뷸러리)
| 모델 | 용도 |
|------|------|
| **SAM / SAM2** | 프롬프트 세그멘테이션(주행가능 영역·장애물 마스크) |
| **Grounded-SAM** | Grounding DINO + SAM = 텍스트→박스→마스크 |

|------|------|------|

| **Claude / GPT-4V** | 고품질 추론·이상진단·리포트 | 클라우드 API (오프보드 분석) |
| **LLaVA / InternVL** | 오픈소스 VLM | 온프레미스 |

## 6. 실행 제약 & 안전 원칙

- **연산**: Jetson(Orin)에서 YOLO-World 등 소형 실시간 가능. 대형 VLM/VLA는 부담 → 클라우드 or 저빈도.
- **빈도 분리**: 제어=20Hz(고전), VLM=~1Hz(감독). VLM을 제어루프에 넣지 말 것.
- **🛑 안전 최우선**: 폭주·프리즈 이력 있는 현 상태에서 **어떤 확률적 모델도 안전제어 경로에 넣지 않는다.** 최종 안전은 **하드웨어 E-stop**(모터 전원 물리차단). VLM은 그 위에 얹는 소프트 인지층일 뿐.
- **이중 안전망**: 치명 클래스(사람)는 **전용 검출(확실)** + 오픈보캐뷸러리로 **예상밖 물체**까지 → 이중.

## 7. 권고 (로드맵)

1. **근시일 파일럿(1순위)**: **YOLO-World**로 전방 프레임 주행 장애물 오픈보캐뷸러리 검출 → 현재 "사람만" 대비 검출력 데모. floor 세그(`floor=주행가능`)와 결합해 "그 외 물체=장애물" 로직.
   - 리스크 대비 이득 최고, 안전제어 밖(인지 보조).
2. **다음**: 결속 품질/이상 검사 VLM(결속 후 이미지 감독).
3. **보류/비추**: VLA end-to-end 제어 — 정밀도·데이터·안전 부적합. 핵심 제어는 고전 유지.
