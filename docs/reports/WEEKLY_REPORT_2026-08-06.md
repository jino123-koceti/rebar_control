## 1. CAD 기반 교차점 위치 검출 알고리즘

### 1.1 배경

기존에는 호모그래피 캘리브레이션으로 컬러 픽셀 → 스테이지 XY를 매핑했다.
호모그래피는 **대상이 단일 평면에 있다는 가정**이 전제인데, 철근 배근은
상·하부 철근이 겹쳐 높이차가 있고 다층 배근에서는 가정이 더 크게 깨진다.
또한 카메라를 재장착하면 전 구간을 다시 캘리브해야 했다.

→ **CAD 배치값에서 직접 강체변환을 유도**하고, 실측으로는 병진 오프셋만
보정하는 방식으로 대체했다 (2026-08-05).

### 1.2 파이프라인

```
컬러 픽셀 (u,v)  +  정합 depth(mm)  +  컬러 intrinsic(fx,fy,cx,cy)  +  자세(r/l)
        │
        ├─ intrinsic 역투영 ─────────▶  P_cam   (카메라 광학 3D, mm)
        │
        ├─ CAD 강체변환 (R, t) ──────▶  P_eef   (결속건 프레임)
        │                                        X=근/원, Y=좌/우, +Z=하강
        │
        └─ 자세별 touch 오프셋 ──────▶  스테이지 XY 명령 (mm)
```

Z(하강)는 결속 시퀀스가 별도 처리하므로 이 단계는 XY만 산출한다.

**전제**: Gemini 2L을 `depth_registration:=true`로 기동해 depth가 컬러에 정합돼
있어야 한다(동일 픽셀 인덱스).

![CAD 변환 오버레이](figures/fig1a_cad_overlay.png)

**그림 1.** Orbbec 컬러 프레임에 검출 교차점과 **변환 결과 스테이지 좌표(mm)** 를
오버레이한 것. 2026-08-06 실장비 캡처. 교차점 9개 검출 중 7개 로컬라이즈, 2개는
depth 소실로 폐기(`P7`, `P9`) — 유효 표본 부족 시 점을 버리는 안전장치가 동작한 예다.

![스테이지 좌표계 복원](figures/fig1b_cad_stage_frame.png)

**그림 2.** 같은 프레임을 스테이지 좌표계로 옮긴 결과(좌: X-Y 평면, 우: 3D).
원근이 큰 사각(斜角) 뷰에서 검출했음에도 **복원된 점들이 직사각 격자를 이룬다**.
실제 배근이 직교 격자이므로, 이 격자성 자체가 변환의 독립적인 정성 검증이 된다.

### 1.3 CAD 강체변환 유도

카메라(LCS002)와 결속건 EEF(LCS001)의 CAD 배치값(축각 회전 + 위치)에서
camera→EEF 변환을 직접 계산한다.

```
R = Re^T · Rc
t = Re^T · (p_cam − p_eef)          →   P_eef = R · P_cam + t
```

| 상수 | 값 |
|---|---|
| `CAM_AXANG` / `CAM_POS` | 축 (0.66, −0.38, 0.65), 138.03° / (−221.43, −18.07, −25.38) |
| `EEF_AXANG` / `EEF_POS` | 축 (0.58, −0.58, 0.58), 120.0° / (267.16, −266.50, −4.98) |
| `EEF_AXIS_FIX_DEG` | 90.0° — 하강축 중심 축보정(근/원 방향이 +X가 되도록) |

좌표계가 서로 다르다는 점이 핵심 함정이었다 — **CAD 글로벌은 Y-up, 장비
스테이지는 −Z-up(+Z가 하강)**. 축 정렬을 `EEF_AXIS_FIX_DEG`로 맞춘다.

### 1.4 자세별 touch 오프셋

변환행렬 (R, t)은 좌/우 자세 공통이고, **병진만 자세별로 다르다**.
결속건이 실제로 닿는 지점과 EEF 원점의 차이를 실측으로 잡았다.

```
stage_XY = P_eef_XY + (dx, dy)
```

| 자세 | dx (mm) | dy (mm) |
|---|---|---|
| r (우측) | −50.8 | 146.8 |
| l (좌측) | −63.8 | **164.4** |

좌측 Y는 실주행 중 159.4 → 164.4로 **+5mm 보정**했다(2026-08-06).

### 1.5 depth 샘플링 — 철근 상면 복원

교차점 픽셀 주변의 depth를 그대로 쓰면 철근 사이 빈 공간(바닥)이 섞여
값이 뒤로 밀린다. 철근 **상면**만 뽑기 위해 근접밴드 방식을 쓴다:

1. (u,v) 주변 9×9 윈도우를 최근 N프레임(기본 5)에서 수집
2. 유효 범위 50~3000mm만 채택
3. **5퍼센타일 + 25mm 이내**(가장 가까운 표면 밴드)만 남겨 평균
4. 유효 표본 10개 미만이면 `None` 반환 → 해당 점 폐기

### 1.6 검증 결과

**2026-08-05, 4점 실측** (P1/P6 = 우측자세, P3/P4 = 좌측자세)

| 지표 | 결과 |
|---|---|
| XY 잔차 | **~2mm** |
| 스케일 | **≈1.0** (배율 보정 불필요) |

스케일이 1.0으로 나온 것은 CAD 배치값과 실제 기구가 잘 맞는다는 뜻이고,
결과적으로 **자세별 병진 오프셋 2개만 실측하면 캘리브가 끝난다**. 호모그래피
방식의 다점 캘리브 대비 절차가 크게 줄었다.

산출물은 `data/calibration/cad_transform_orbbec.yaml`에 R, t, 자세별 오프셋,
출처 CAD 값, 검증 이력까지 함께 저장된다.

## 2. 자율작업 — 전·후진 주행 + 주행가능영역 + 결속

### 2.1 개념

좌표를 미리 모르는 상태에서 **보이는 배근을 따라가며** 결속한다.
기존 UI 웨이포인트 주행[A]과 달리 반응형이라 별도 노드로 분리했다.

```
  [A] UI 웨이포인트 ─▶ navigator ─▶ rebar_controller ──┐
  [B] 배근인지 자율 ─▶ rebar_drive_node ───────────────┴─▶ /cmd_vel ─▶ drive_controller
                            ▲                                            ▲
                            └─ /deck_edge_status ─ deck_edge_node ─ /deck_edge_block
                            │
                            └─ /mission/command ─▶ tying_orchestrator
                                                   └─▶ TYING_COMPLETE:<n>
```

`/cmd_vel`은 A가 우선권을 갖고 B가 비킨다. A가 주행 중이면 B는 시작을 거부하고,
주행 중 A가 개입하면 즉시 양보(ABORT)한다.

### 2.2 상태머신

```
IDLE ─S23─▶ FWD_DETECT ⇄ FWD_STEP ─(배근끝)─▶ FWD_SETTLE
       ─▶ REV_DETECT ⇄ REV_STEP ─(배근끝)─▶ REV_SETTLE ─▶ DONE

    S24 / estop / S20 해제 / A 개입 → ABORT
```

한 사이클: **검출 → 간격 측정 → 결속 대상 선별 → 결속 → 다음 이동거리 산출 → 스텝 주행**

### 2.3 다음 웨이포인트 생성 알고리즘

`coverage_planner.py` — ROS 무관 순수 함수로 분리했다.

**(a) 격자 복원**

검출된 교차점(로봇 XY)을 1D 클러스터링한다. X 클러스터 = 열(column),
Y 클러스터 = 행(row). 허용 오차 50mm.

**(b) pitch 추정 — 결측 열 자동 보정**

인접 클러스터 간격에서 배근 간격을 구하는데, 검출이 열을 놓치면 2×·3× 간격이
섞인다. 최소 간격의 정수배로 정규화해 1×로 복원한 뒤 중앙값을 쓴다:

```
norm[i] = diff[i] / round(diff[i] / min_diff)
pitch   = median(norm)
```

폴백 순서: **결속범위 안 실측 → 검출 전체 실측 → 이전 pitch → 기본값 195mm**.
양축 모두 실측이면 신뢰도 `high`, 아니면 `low`로 표기한다.

**(c) 이동거리 산출**

```
d = (마지막 결속 열의 X) − (결속 도달범위 시작) + clear_margin(30mm)
    단, 최소 1 pitch 보장 (제자리걸음 방지)
```

원리: 도달범위 안 교차점은 모두 결속했으므로, **마지막 결속 열을 지나칠 만큼**
전진하면 다음 미결속 열에 선다. 유효 구간은
`마지막 열 < d ≤ 마지막 열 + pitch`이고, 아래로 벗어나면 재결속, 위로 벗어나면
열 누락이 된다.

![웨이포인트 생성](figures/fig2_waypoint_generation.png)

**그림 3.** 2026-08-06 실주행 4사이클의 격자 복원과 이동거리 산출. 파란/주황 영역이

### 2.4 주행가능영역 판정 (deck_edge)

배근 seg 마스크의 `rebar_frac`(화면 내 배근 비율)으로 주행 가능 여부를 낸다.

| 임계 | 값 | 동작 |
|---|---|---|
| `stop_thr` | 0.45 | STOP — 스텝 미완이어도 즉시 중단 |
| `slow_thr` | 0.55 | SLOW — 속도 배율 0.4 |

- 진행방향 카메라만 추론(`active_only`)해 GPU 부하를 줄인다. 총 4Hz.
- 판정이 1.0s 끊기면 중단, 단 첫 판정은 8.0s 유예(DDS 디스커버리 경합 회피).
- `/deck_edge_block`은 A·B 공통 안전망으로 drive_controller가 직접 소비한다.

주행가능면을 **철근 배근으로 한정**한 것이 이번 주 변경점이다. 구버전은
background(방수포)를 주행가능에 포함했는데, 배근 없는 맨 방수포 위를 GO로 오판했고
카메라별 baseline도 갈렸다. 철근 기준으로 바꾸자 **front/back 공통 임계**를 쓸 수
있게 됐다(카메라 무관).

![주행가능영역 판정](figures/fig4_deck_edge.png)

**그림 4.** 배근 끝에 근접시킨 상태의 전·후방 판정 (2026-08-06 캡처).

멀리까지 이어짐). 방향별로 독립 판정하기 때문에 배근 끝에 서더라도 **왔던 방향으로
빠져나가는 경로는 막지 않는다**. 두 값 모두 실측 대역(정상주행 0.55~0.68 /
데크끝 0.17~0.47)에 정확히 들어온다.

## 3. 실주행 검증 (2026-08-06)

첫 실구동 + 실결속 통합 테스트. 전진 2사이클 → 배근 끝 감지 → 후진 2사이클.

| # | 방향 | 결속범위내 격자 | pitch 신뢰도 | 결속 | 목표 이동 | 실제 |
|---|---|---|---|---|---|---|
| 1 | 전진 | 열2×행2 | high | 3점 | 258mm | 243mm |
| 2 | 전진 | 열2×행2 | high | 4점 | 319mm | 배근끝 감지로 중단 |
| 3 | 후진 | 열1×행2 | low | 2점 | 179mm | 164mm |
| 4 | 후진 | 열2×행2 | high | 5점 | 331mm | S24 수동 정지 |

**누적 결속 14점. 예외·타임아웃·판정 누락 없음.** 로그의 유일한 ERROR는
의도된 S24 정지다.

![사이클 타임라인](figures/fig3_cycle_timeline.png)

**그림 5.** 좌: 사이클별 시간 분해(검출·결속·주행). 우: 결속 점수 대비 소요시간.

시간 구성이 뚜렷하다 — **총 167초 중 결속이 118.6초(71%)** 로 지배적이고,
검출은 5.4초(3%)에 불과하다. 검출 파이프라인은 이미 병목이 아니며,
사이클 타임을 줄이려면 결속 시퀀스를 손봐야 한다.

결속 시간은 점수에 대해 거의 선형이다:

```
결속시간 ≈ 6.2 s/점 + 7.9 s (고정 오버헤드)
```

고정분 약 8초는 자세 변경·스테이지 이동 등 점수와 무관한 비용으로 보인다.
점당 6.2초와 분리해서 봐야 개선 여지를 판단할 수 있다.

첫 사이클의 검출만 2.50초로 유독 길고(이후 0.95~0.98초) YOLO 워밍업 비용으로 보인다.

검증된 항목:

- 검출 → 결속 → 이동 사이클이 끊김 없이 반복
- 전방 카메라 기반 배근 끝 감지로 스텝 중간 안전 정지 (`rebar_frac=0.45`)
- 방향 전환 시 후방 카메라 첫 판정이 유예시간 내 수신, 전환 1.5s
- 감속 프로파일 정상 (잔여 73mm부터 vx 0.100 → 0.050)
- 결속 소요 점당 약 7~8초 (3점 26.5s / 4점 33.0s / 2점 20.0s / 5점 38.7s)

## 4. 이번 주 해결한 회귀

실주행에서 드러난 설계 결함 3건을 수정했다. 셋 다 **"어떤 범위의 교차점을
무엇에 쓰는가"**를 혼동한 데서 나왔다.

### (1) 이동거리를 `열수 × pitch`로 계산 → 재결속 발생

`열수 × pitch`는 **첫 열이 도달범위 시작에 있을 때만** 성립한다.

실측: 열 `[154.7, 311.6]`, pitch 156.9 → 313.8mm 지령. 유효 하한(311.6)보다
2.2mm 큰 값이라 여유가 없었고, 도달오차 14mm가 겹쳐 실제로는 300mm만 이동해
311.6 열이 11.6mm 지점에 남아 **재결속**됐다.

→ **마지막 결속 열 기준 + 마진 30mm**로 변경. 마진은 도달오차를 덮을 만큼 준다.

### (2) 검출에 결속 도달범위를 사용 → pitch 측정 실패

도달범위는 스테이지가 닿는지를 거르는 필터인데, 주행은 도달 여부와 무관하게
격자 **간격**만 알면 된다. 실측에서 7개 검출 중 6개가 '범위밖'으로 버려져
교차점 1개만 남았고 pitch가 기본값(195mm)으로 떨어졌다.

→ pitch 측정용 범위를 ±3000mm로 넓게 열었다.

### (3) 자세 분류에 넓힌 검출범위를 사용 → 지그재그 미동작

(2)의 수정 부작용. 범위를 넓히자 로컬라이저가 교차점을 **전부 우측(r)으로
분류**해 좌측이 항상 0점이 됐고, orchestrator의 지그재그(우 → 자세변경 → 좌)가
일어나지 않았다.

→ **pitch 측정용(넓은 범위)과 결속 자세분류용(실제 도달범위)을 분리**했다.
자세별 Y 도달범위는 `tying_orchestrator.yaml` 실측치와 동기한다
(우 0~142mm, 좌 124~288mm).

## 5. 남은 과제

| 우선순위 | 항목 | 내용 |
|---|---|---|
| 높음 | 스텝 이동거리 −15mm | 243/258, 164/179 모두 정확히 −15mm. `tolerance_mm`(15.0)와 일치해 도달 판정 조기 종료로 추정. 누적 여부 확인 후 목표거리 보정 검토 |
| 높음 | 조향 로직 검증 | `heading_enabled` 기본 false라 이번 테스트에서 미동작. 부호 규약은 실측 확정(angular.z 양수 = 좌회전, 후진 반전). 저속에서 방향·강도 검증 필요 |
| 중간 | 후진 진입 직후 pitch low | 배근 끝 근처라 결속범위 안 열이 1개뿐. 한 스텝 후 회복돼 일시적 현상으로 보이나 반복 시 검출자세 Y 재검토 |
| 중간 | pose_mux odom 미가동 | zedxmini가 `depth_mode:=NONE`이라 ZED 래퍼가 positional tracking을 거부. [A] 웨이포인트 주행에 필요하나 GPU 부하 증가와 상충 |
| 낮음 | 다층 배근 대응 | `DEPTH_Z_OFFSET_MM`(317.5) 경로는 구현돼 있으나 미검증 |

### 조향 게인을 낮게 잡은 이유 (기록)

RC 테스트베드는 **배근이 고정돼 있지 않다.** 궤도가 배근 위에서 자주·세게
비틀리면 격자가 밀려 무너진다. 그래서 정렬 정확도보다 배근 보존을 우선해
게인을 러프하게 잡아뒀다(`kp=0.008`, `max=0.04 rad/s`, 데드밴드 2°).
실제 데크에서는 키워도 된다.
