# 배근 인지 자율작업 — 격자·플래너 설계

작성 2026-10-17. 2차년도 `rebar_drive_node`(1,777줄)를 읽고, 거기에 **없던 것**을
채우는 설계다. 2차년도 동작·함정 분석은 이 문서 끝의 §9 에 요약해 두었다.

---

## 1. 무엇을 풀려고 하는가

2차년도 자율주행에는 **지도가 없다.** 아는 것은 "지금 이 방향으로 더 갈 수 있나"
하나뿐이라, 다음 두 가지가 구조적으로 불가능하다.

1. **중간에 막힌 자리를 건너뛰고 나중에 돌아오기.** 막힌 칸과 배근 끝을 구별하지
   못해서, 레인 중간이 막히면 그 레인의 나머지를 통째로 버린다.
2. **미결속 지점 추적.** 결속 이력은 "다시 쏘지 않기 위한 제외 목록"이지
   "아직 안 한 곳" 목록이 아니다.

사용자 예시로 말하면 — 가로 1·2·3, 세로 A·B·C 에서 B3 가 막혔을 때
`A1 A2 A3 → A2 → B2 B1 → C1 C2 C3` 로 가는 것이 목표다. 2차년도는
`A1 A2 A3` 뒤에 B 레인을 포기한다.

**범위.** 이 문서는 지도(격자)와 플래너까지다. 주행·검출·결속은 이미 있는
3차년도 노드를 그대로 쓴다.

## 2. 전제 — 측정된 수치

설계가 기대고 있는 값들이다. **바뀌면 이 문서를 다시 봐야 한다.**

| 항목 | 값 | 출처 |
|---|---|---|
| 한 정차지 결속 가능 영역 | **주행방향 520mm × 횡방향 380mm** (0.197 m²) | 캘리 모델 × 가동범위로 계산 (2026-10-17) |
| 그 영역의 직사각 충전율 | 98% | 같음 — 거의 사각형이라 격자로 다뤄도 손실이 작다 |
| 스테이지 스트로크 (3차년도) | X 453.7 · Y 349.1 · Z 139.2mm | `axes.yaml`. 가동범위는 이보다 **좁다**(기구 간섭) |
| 장비 몸체 | **940 (폭) × 1160 (길이) mm** (실측 2026-10-17) | 통로 통과 판정의 기준. 2차년도(1037×720)와 가로세로가 반대다 |
| 몸체 중심축 | **결속영역 중심축과 일치** (확인 2026-10-17) | 치우침 없음 |
| 통과 가능 최소 틈 | 횡 **1060** · 종 **1280mm** (여유 ±60) | `coverage_space` |
| 주행 1스텝 정밀도 | 허용오차 5mm (`drive_node` `tol_mm`) | 바퀴 각도 폐루프 |
| 주행 순항 속도 | 0.08 m/s (근접 0.025) | `drive_node` 기본값 |
| 횡이동 단위 | **1회전 = ?mm** — §10 미결 | 코드 100mm / 사용자 50mm 충돌 |
| 횡이동 속도 | 50 dps → 1회전 7.2초 | `lateral_node` 기본값 |
| 검출 자세 제약 | X 를 뺀 상태여야 한다 (X>380 이면 건이 카메라를 가림) | `tying_planner` 주석, 2026-10-04 실측 |

⚠ **단위 주의.** 전에 이 값을 460 × 370mm 로 적었는데 그건 **카메라 좌표** 였다.
카메라가 철근 평면에 29° 기울어 있어 cam_y 방향이 cos29° 만큼 단축돼 보인다
(460 / cos29° = 526). 평면상 실제 치수는 **정준 좌표(1번 자세 스테이지 mm)**
기준 520 × 380mm 다. 격자·플래너는 전부 정준 좌표를 쓰므로 계산은 옳았고,
**문서의 숫자만 틀렸다.**

결속 가능 영역의 자세 분담은 이렇게 갈린다 (카메라 좌표, 로봇 고정):

```
         ← 횡방향(cam_x) →
  +120 |    444444411111111111       |   1 = 1번 자세
    +0 |    4444444111111111112      |   2 = 2번
  -120 |    4333333111111111112      |   3 = 3번
  -240 |     333333322222222222      |   4 = 4번
  -320 |     333333333333            |   . = 어느 자세로도 불가
```

축 대응은 캘리 모델에서 바로 나온다 — `cam_y → 스테이지 X(주행방향)`,
`cam_x → 스테이지 Y(횡방향)`. 깊이는 평면이라 `depth ≈ 448.6 − 0.556·cam_y`
(짝 83개, 잔차 RMS 6.7mm)로 대체된다.

## 3. 핵심 결정 — 지도는 **철근 격자**, 계획은 **정차지 단위**

자유격자(예: 600×400mm 칸)를 깔지 않는다. **철근 교차점 자체가 격자다.**

이유가 셋이다.

1. **드리프트에 강하다.** 자유격자는 오도메트리 오차가 그대로 칸 번호 오차가
   된다. 교차점 격자는 매 정차마다 다시 보므로 관측이 계속 보정해 준다.
2. **"아직 안 한 곳"이 자연스럽게 정의된다.** 셀 = 교차점이므로 미결속 집합이
   곧 할 일 목록이다.
3. **2차년도가 이미 이 방향으로 반쯤 와 있었다.** `_col_abs`(열을 절대좌표로
   기억하고 누적평균으로 갱신)가 정확히 격자 추적이다. 다만 열(1차원)뿐이었고
   미결속을 기억하지 않았다.

계획은 교차점 단위가 아니라 **정차지 단위**로 한다. 한 번 서면 460×370mm 안의
교차점을 여러 개 묶어 결속하므로, 점마다 계획하면 의미가 없다.

```
  지도     : 교차점 격자 (셀 = 교차점 하나, 상태를 가진다)
  계획     : 정차지 (로봇 포즈) — 한 정차지가 여러 셀을 덮는다
  실행     : 기존 노드 (drive_node / lateral_node / tying_planner)
```

## 4. 좌표계와 드리프트

### 4.1 세 좌표계

| 이름 | 정의 | 쓰임 |
|---|---|---|
| 카메라 좌표 | 상부체 고정. 검출기가 내는 mm | 검출 → 결속 (이미 쓰고 있다) |
| 작업 좌표 | 자율작업 **시작 지점**에 고정한 2D 평면 | 지도·플래너 |
| 격자 지수 | 작업 좌표를 피치로 나눈 정수 (i, j) | 셀 식별 |

작업 좌표는 누적으로 만든다 — 주행은 `drive_node` 가 실제로 간 mm,
횡이동은 회전수 × mm/회전. **절대 위치추정(SLAM)은 하지 않는다.**

### 4.2 드리프트를 격자로 잡는다

누적만으로는 긴 작업에서 센티미터 단위로 밀린다. 그런데 교차점 격자는 주기적이라
**관측을 격자에 맞추면 누적 오차가 1피치 안으로 묶인다.**

매 정차의 검출마다:

1. 검출된 교차점을 누적 포즈로 작업 좌표에 올린다
2. 각 축에서 **격자와의 평균 어긋남**을 구한다 (피치로 나눈 나머지의 원형 평균)
3. 그 값으로 누적 포즈를 보정한다

⚠ 이것은 **1피치 모호성**을 가진다 — 반 피치 넘게 밀리면 옆 칸에 붙는다.
한 스텝 이동이 1피치보다 작도록 계획하면(아래 §6) 그 상황이 안 생긴다.
2차년도가 이 보호 없이 고정 병합범위를 썼다가 "1202 로 고정 → 1308 이 106mm
떨어져 신규로 샘" 을 겪었다. 누적평균 갱신도 같이 둔다.

### 4.3 피치 추정

`coverage_planner.estimate_pitch`(2차년도, ROS 무관)를 **그대로 가져온다.**
결측 열 때문에 2×·3× 간격이 섞여도 최소간격의 정수배로 정규화해 복원하는
로직이 들어 있고, 순수함수라 이식 비용이 거의 없다.

## 5. 셀 상태

```
            검출에서 처음 보임
                  ↓
  unknown ──▶ pending ──결속 성공──▶ tied
                 │
                 ├── 이미 결속됨으로 분류 ──▶ tied
                 ├── 결속 실패(재시도 남음) ──▶ pending (retry+1)
                 ├── 결속 실패(재시도 소진) ──▶ failed
                 └── 도달 불가/장애물 ──▶ blocked
```

| 상태 | 뜻 | 어디서 오나 |
|---|---|---|
| `unknown` | 격자상 있을 법한데 아직 못 봄 | 피치 외삽 |
| `pending` | 봤고, 아직 안 묶음 | `/rebar/crossings` |
| `tied` | 묶음 | `/plan/status` 의 점별 `완료` |
| `failed` | 재시도 소진 | `/plan/status` 의 점별 `실패:…` |
| `blocked` | 접근 불가 | deck_edge STOP · 범퍼 · 가동범위 거부 |

⚠ `unknown` 과 `pending` 을 구별해야 한다. 안 보이는 것은 "없다"가 아니다 —
건이 가렸을 수도 있고(2026-10-16 에 건이 교차점 4개를 가린 적이 있다) 검출이
놓쳤을 수도 있다. `unknown` 은 완료 판정을 막지 않지만, 근처에 갈 일이 생기면
한 번 더 보게 한다.

⚠ `blocked` 에는 **사유와 시각**을 같이 남긴다. "범퍼에 눌려서"와 "가동범위
밖이라서"는 나중에 다시 가 볼 가치가 다르다.

## 6. 플래너

### 6.1 후보 정차지 생성

자유격자를 훑지 않는다. **미결속 셀에서 후보를 만든다.**

```
  for 각 pending 셀 c:
      후보 ← 결속영역의 중심이 c 에 오는 로봇 포즈
  후보들을 횡방향으로 양자화한다 (횡이동 1회전 단위 — 그 이하로는 못 선다)
```

주행방향은 연속(5mm 분해능)이고 횡방향은 회전수 단위라 **비대칭**이다.
이 비대칭이 설계에 그대로 들어가야 한다 — 2차년도가 횡이동 회전수를 고르다가
두 번 틀렸다(최소 회전 → 70mm 만 이동, 올림 → 1회전 낭비).

### 6.2 고르는 기준

각 후보에 대해:

```
  이득 = 그 자리에서 새로 묶을 수 있는 pending 셀 수
  비용 = 이동시간(주행 mm, 횡이동 회전수) + 정차 오버헤드
  점수 = 이득 / 비용
```

가장 높은 점수를 고른다. 동점이면 **횡이동이 없는 쪽**을 고른다.

이것만으로 B3 시나리오가 풀린다. A3 에서 B3 가 blocked 면, B2 를 덮는 후보가
"A2 쪽으로 조금 물러나 횡이동" 으로 나오고, 그 비용이 다른 후보보다 싸다.
지그재그도 보상 설계 없이 **비용 비율에서 저절로 나온다** — 횡이동 1회전이
7.2초인데 같은 거리 주행은 1~2초다.

### 6.3 비용 상수

⚠ **아직 실측이 없다.** 아래는 자리만 잡아 둔 값이고, 붙이기 전에 재야 한다.

| 항목 | 임시값 | 재는 법 |
|---|---|---|
| 주행 | 거리/70mm/s + 2s | `/drive/status` 로그 |
| 횡이동 | 회전수 × 7.2s + 3s | `~/lateral_logs/*.csv` |
| 검출 | 1.0s | `crossing_detector` 로그 |
| 결속 1점 | ? | 결속 사이클 로그. **park 만 22.5초**라는 것은 안다 |
| 자세 변경 | 20초+ | `tying_planner` 주석 |

결속·자세변경이 이동보다 훨씬 비싸면 **"이득" 쪽이 지배**한다 — 즉 한 번 서서
최대한 많이 묶는 것이 정답이 되고, 이동 최적화의 실익은 작다. 상수를 재고
나서 플래너를 복잡하게 할지 정하는 게 맞다.

### 6.4 종료

`pending` 이 0 이고 `unknown` 중 도달 가능한 것이 없으면 완료.
`failed`/`blocked` 는 남겨 두고 **사유와 함께 보고**한다 — 조용히 끝내면
사람이 빠진 걸 모른다.

## 7. 바깥 상태기계

```
  IDLE ─시작─▶ DETECT ──▶ TIE ──▶ PLAN ──▶ MOVE ──┐
                 ▲                                 │
                 └─────────────────────────────────┘
                              ↓ (pending 0)
                            DONE
```

2차년도의 `FWD_*`/`REV_*` 를 **방향 없는 한 벌로 합친다.** 방향은 플래너가
정하는 결과지 상태가 아니다. 2차년도가 방향별로 상태를 둔 탓에 "전진 끝 →
무조건 후진" 이 구조에 박혀 버렸다.

### 7.1 반드시 지킬 것 (2차년도 실주행에서 배운 것)

| 규칙 | 왜 |
|---|---|
| **결속 완료를 기다리는 동안 주행 판정으로 빠지지 않는다** | 2026-09-15 사고. 상부가 Z하강·트리거 하는 동안 하부가 기체를 들어 옆으로 옮겼다 |
| **STOP 은 연속 N프레임 확인 후에만 수용**, 전환 커밋 직전 재확인 | 기둥 지날 때 같은 초에 GO→STOP→GO 로 뒤집혀 레인 하나를 통째로 건너뛰었다 |
| **횡이동은 1회전씩 쪼개고 매 회전마다 재판정** | 일괄 지령하면 2회째에 배근이 끊겨도 못 멈춘다 |
| **횡이동 방향 부호를 눈으로 1회전 확인** | 2차년도에 `left` 지령에 우측으로 갔다. 재판정이 보는 쪽과 가는 쪽이 반대가 되어 안전장치가 통째로 무력화됐다 |
| **상태 전이를 fsync 로 남긴다** | 프리즈 때 어느 상태였는지 몰랐다 |
| **범퍼 차단 시간은 타임아웃에서 뺀다** | 안 빼면 범퍼를 누른 것만으로 타임아웃 |
| **검출은 X 를 뺀 자세에서** | X 380mm 넘으면 건이 카메라를 가린다 (3차년도 실측) |
| **호밍은 항상 전 축** | 축별 간섭 구간이 달라 건너뛰면 프레임을 친다 |

## 8. 구성과 구현 순서

### 8.1 파일

| 새 파일 | 성격 | 예상 줄수 |
|---|---|---|
| `rmd_robot_control/coverage_map.py` | **ROS 무관 순수 모듈.** 격자·셀 상태·피치·후보 생성·점수 | 400 |
| `rmd_robot_control/auto_node.py` | 바깥 상태기계. 위를 들고 기존 노드에 명령 | 600 |
| `tools/test/coverage_sim.py` | 지도·플래너 단독 시뮬 (장비 없이) | 300 |

ROS 무관 모듈을 떼는 것은 2차년도에서 효과가 증명된 선택이다 —
`coverage_planner.py` 가 그래서 자가테스트가 됐다. R4 상한에 두 항목 추가 필요.

### 8.2 순서 — 장비 없이 갈 수 있는 데까지 먼저

| 단계 | 내용 | 검증 | 장비 필요 |
|---|---|---|---|
| 1 | `coverage_map` + 2차년도 `estimate_pitch` 이식 | 단위테스트 | **없음** |
| 2 | `coverage_sim` — 격자·장애물을 넣고 플래너 경로를 그려 본다 | B3 시나리오가 `A1 A2 A3 A2 B2 B1 C1 C2 C3` 로 나오는가 | **없음** |
| 3 | 비용 상수 실측 | 로그 분석 | 결속 1사이클 |
| 4 | `auto_node` 껍데기 + dry-run (명령 안 냄) | 실제 검출을 먹여 계획만 출력 | 정차 상태 |
| 5 | 한 레인 자율 (횡이동 없이) | 전진·결속 반복 | 주행 |
| 6 | 횡이동 포함 전 영역 | | 주행 + 횡이동 |
| 7 | deck_edge 연동 | | **ZED X 필요** |

⚠ **ZED X 는 7단계에서만 필요하다.** 전후방 카메라가 하는 일은 "데크 밖으로
떨어지지 않기"(안전)이고, "어디까지 작업할지"(커버리지)는 교차점 검출기가 이미
답한다 — 앞쪽에 미결속 교차점이 없으면 거기가 끝이다. 그러니 **카메라를 기다리지
않고 1~6단계를 할 수 있다.** 다만 6단계까지는 사람이 보는 앞에서만 돌린다.

## 9. 2차년도에서 가져오는 것 / 버리는 것

| 2차년도 | 처리 |
|---|---|
| `coverage_planner.estimate_pitch` | **그대로 이식** (순수함수) |
| `coverage_planner.compute_next_move` | **버린다** — "마지막 열 + 마진" 규칙은 지도가 있으면 불필요 |
| `_col_abs` 절대좌표 열 기억 | **개념을 2D 로 확장**해 격자 추적으로 |
| 결속 이력(`_already_tied`) | **셀 상태로 흡수** |
| 밀도(`tie_every_n`) | **유지** — 셀을 건너뛰는 규칙으로 다시 표현 |
| `FWD_*`/`REV_*` 상태 분리 | **버린다** — 방향은 플래너의 결과 |
| 횡이동 1회전 쪼개기·재판정 | **그대로** |
| `deck_edge_node` | **유지** (안전). 카메라 경로만 3차년도에 맞춘다 |
| 작업도 기록(JSONL) | **유지·강화** — 지도 스냅샷까지 남긴다 |

## 10. 미결 사항

1. **횡이동 1회전이 몇 mm 인가.** `lateral_axes.MM_PER_TURN = 100.0` 과
   `lateral_node` 주석 50mm 가 충돌하고, 사용자는 50mm 라고 했다.
   횡방향 양자화 단위라 플래너에 직접 들어간다 — **재서 하나로 고칠 것.**
   (코드는 `/lateral/step` 으로 **회전수**를 받으므로, 상수만 바로잡으면 된다)
2. **S23/S24 용도.** 자율 시작·정지에 쓸지, 다른 데 쓸지 미결 (인벤토리 C5 vs G3).
3. **결속 사이클 비용** 실측 — §6.3.
4. **재시도 정책.** 결속 실패를 몇 번까지, 같은 정차에서 다시 할지 다음에 들를 때
   할지. 충돌로 실패한 자리는 좌표가 틀린 것이므로 같은 좌표로 재시도해도 소용없다
   — 카메라 폐루프 보정([[rebar-calib-close-loop-with-camera]])과 묶어야 한다.
5. **2층 배근.** 하단근×상단근이 탑뷰에서 교차점처럼 보인다. 2차년도에 `layer_mode`
   가 있었지만 현장 미검증이었다. 3차년도 RC 목업에서 갈리는지 확인 필요.
