# 멀티턴 절대 위치 — 호스트측 랩 복원 하이브리드 설계

**작성**: 2026-06-15
**대상**: `rebar_base_control` (joint_controller / homing_controller / can_parser)
**배경 결정**: 모터 멀티턴 전원오프 저장이 급전원차단에 실패함이 확정됨 → SW로 우회.

---

## 0. 배경 (실측·프로토콜 확정)

- **모터 멀티턴 저장(0x20 idx=0x04) 실패**: 프로토콜 §2.35는 "save the multi-turn value **before powering off**"라 명시 — graceful 종료 전제. 케이블 급탈거(brownout)엔 저장 미완료.
- **실측 재현**: x_min에서 0x92 382°→21°, 랩+4에서 1462.64°→21.46° (정확히 −4턴). raw 0x61도 함께 붕괴(1228976→179543). 영점 0x62는 유지(163914).
- **결론**: 부팅 시 모터가 보존하는 건 **단일턴(0~360°)뿐**, 랩카운트는 0x60/0x61 모두 소실. write 명령(0x63/0x64)으로도 복원 불가(복원할 랩 정보가 모터에 없음).
- ✅ **단일턴(0x94)·영점(0x62)은 전원오프에 유지** → 이걸 기반으로 SW가 랩을 대신 기억.

## 1. 핵심 아이디어

**모터가 못 지키는 턴수(랩카운트)를 PC 파일이 대신 기억**한다.

```
절대위치 = (PC 파일의 턴수 × 360°) + (모터 단일턴 0x94)
```

## 2. 부팅 복원 흐름 (축별 독립)

```
부팅
 ├─ 각 축: 파일의 단일턴성분  vs  모터 0x94(현재 단일턴)  비교 (허용오차 ±2~3°)
 │
 ├─[일치]──────→ 전원오프 중 무이동 → 신뢰
 │                절대위치 = 파일턴수×360 + 0x94 → 절대 엔코더 기준 동작
 │
 └─[불일치 / 파일없음·손상]→ 전원오프 중 이동(또는 첫부팅) → 신뢰 안 함
                  → 기존 호밍 시퀀스 수행 → 리미트에서 절대값 재확인
                  → ★ 그 값을 파일에 덮어씀 → 절대 엔코더 기준 동작
                                              ↓
              ★ 두 경로 모두 "절대 엔코더 기준 동작"으로 수렴 ★
```

호밍은 **"파일을 신뢰할 수 없을 때만"** 작동하는 재앵커링 + 파일교정 역할로 격하.
→ 평소엔 호밍 없이 즉시 절대 복원, 누가 건드렸을 때만 호밍.

## 3. 운용 중 — 위치 지속 저장

- 절대위치를 파일에 **계속 갱신**(예: 20Hz 또는 위치변화 시).
- **atomic write**(temp 파일 → rename): 급전원차단·쓰기중 차단에도 파일 안 깨짐.
- 파일 포맷(축별): `{ motor_id, abs_deg, single_turn_deg(0x94), ts }`

## 4. SW 랩 오프셋 처리

모터 0x92는 부팅 때 랩0 기준으로 시작하므로, 제어 노드가 부팅 시 `lap_offset`을 결정하고 환산:

```
lap_offset = 복원된_절대위치 − 부팅직후_모터0x92      (일치 경로: 파일 / 불일치 경로: 호밍)
실제위치(운용) = 모터0x92 + lap_offset
```

운용 중 모터는 powered-on 상태라 0x92가 연속 추적 → 세션 내 일관.

## 5. 사용 CAN 명령 (V4.3 프로토콜 확정)

| 명령 | 용도 | 비고 |
|---|---|---|
| **0x94** Read Single-Turn Angle | 정합성 검사용 단일턴 (0~359.99°, 0.01°, 영점기준) | 전원오프 유지 ✅ |
| **0x92** Read Multi-Turn Angle | 운용 위치(부팅시 랩0 기준) | lap_offset로 환산 |
| 0x60/0x61/0x62 | 진단용(raw/offset) | 0x62 변경 감지 시 재앵커링 |

## 6. 엣지 케이스 / 안전

- ⚠️ **정수턴 함정**: 전원오프 중 정확히 360°(X 80mm) 배수로 움직이면 단일턴은 맞고 턴수는 틀림 → 거짓신뢰. **리드스크류라 자유회전 불가**가 핵심 전제. (Yaw는 ~1턴이라 무관)
- **파일 없음/손상 → 호밍 폴백** (안전 기본값, 첫 부팅 포함).
- **0x62(영점) 변경 감지 → 호밍 재앵커링** (0x64 ROM 리셋 등).
- **허용오차**: 단일턴 비교 ±2~3°(엔코더 노이즈 ~1° 실측). mm 환산 기준 별도 검토.
- 축별 독립 판정 — 일부 축만 불일치면 그 축만 호밍.

## 7. 로드맵 관계

- 이 설계가 **죽은 Phase 2(멀티턴 영속 config 상수)를 대체**.
- **Phase 6 동적 자세 플래너는 영향 없음**(운용 중 powered-on 위치만 필요, 영속성 무관).
- Yaw(~1.1턴)는 정수턴 함정 거의 없어 가장 먼저/안전하게 적용 가능.

## 8. 구현 순서(안)

1. 위치 지속 저장 모듈 (어느 노드에서 20Hz atomic write할지 — joint_controller 후보)
2. 부팅 복원 로직 (0x94 읽기 → 파일 비교 → lap_offset 설정 / 호밍 트리거)
3. 호밍 완료 시 파일 덮어쓰기 훅
4. Yaw 우선 적용 → X/Y/Z 확대 → 회귀시험(100pt)
