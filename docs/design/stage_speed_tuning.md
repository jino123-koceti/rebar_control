# 상부축(XYZ) 속도 튜닝 — 2026-11-09 실측

> 결속 점당 시간을 줄이려고 Z·XY 속도와 브레이크 유예를 건드려 본 기록이다.
> **무엇이 통했고 무엇이 안 통했는지**, 그리고 다음에 어디를 파야 하는지를 남긴다.

---

## 0. 출발점 — 점당 시간은 어디에 쓰이나

자세 유지 점 하나(7.55초)의 실제 타임라인 (18:14 회차, 로그에서 그대로):

```
+0.00  [run]                         플래너가 점을 낸다
+0.30  [precheck] → [move_xy]        플래너→시퀀스 오버헤드  0.30초
+0.35  이동 시작 (X 139mm, Y 87mm)
+3.00  [z_down]                      XY 이동    2.65초   ← 35%
+4.60  [fire]                        z_down     1.60초   ← 21%
+5.85  [z_up]                        fire       1.25초   ← 17%
+7.55  [done]                        z_up       1.70초   ← 23%
```

자세 변경 점(12.0초)은 여기에 `retract 3.41초 + rotate 2.85초` 가 붙는다.

⚠ **단계별 중앙값을 따로 구해서 더하면 안 된다.** 같은 단계가 두 번 로그되는
경우가 있어 중복 제거하면 점유 시간이 깎이고, "설명 안 되는 2.9초" 같은
허깨비가 생긴다 (이번에 실제로 그렇게 헛짚었다). **점 하나의 타임라인을
통째로** 봐야 한다.

목표는 6점/30초 = **5초/점**. 현재 자세 유지 8.5~9.0초로 **1.7~1.8배**다.

## 1. Z 축 — 프로파일

90mm 왕복을 모터 위치(12Hz)로 재서 대기와 이동을 분리했다.

```
하강 90mm   전체 2.64초   전류 중앙 0.42A  최대 0.82A
상승 90mm   전체 3.38초 = 시작지연 1.39초 + 이동 1.86초 (48.4mm/s)
                          전류 중앙 1.37A  최대 1.92A
```

- **상승이 하강보다 전류를 3.4배 쓴다.** 중력을 거스르니 당연하다.
- 명령은 `move_speed_mm_s_z = 60`, 실측 이동 48.4mm/s.
- Z 는 이미 모터 속도 상한 근처다: `60 ÷ 0.090606 = 662dps`, `max_speed_dps 700`.
  **속도만 올리려면 `max_speed_dps` 도 같이 올려야 한다.**

### 시도 ① Z 브레이크 유예 — **상쇄되어 이득 없음**

`z_up` 의 1.39초 시작지연은 브레이크 재해제 대기다. `brake_hold_axes` 에
Z 가 빠져 있어 하강 도착 즉시 잠그고, 상승 때 다시 푼다.

**먼저 처짐을 쟀다** (서보 켜진 상태로 브레이크만 해제, 3초 관찰):

```
처짐 0.000mm  (위치 토픽 12Hz · 36표본)
```

→ 서보가 켜져 있으면 안 처진다. 메모의 "브레이크 풀면 출력축 12.7° 낙하" 는
**서보까지 꺼졌을 때**(전원 차단·`0x80`) 이야기다.

그래서 `brake_hold_axes = x,y,yaw,z` / `brake_hold_sec = 3.0` 으로 시험:

| 단계 | 변경 전 | 변경 후 | 차이 |
|---|---|---|---|
| `z_up` | 2.25초 | 1.85초 | **−0.40** |
| `z_down` | 1.60초 | 2.07초 | **+0.47** |
| `retract` | 0.82초 | 0.05초 | −0.77 |
| 점당(자세 유지) | 8.99초 | 9.00초 | **±0** |

**결론: 원복했다.** `z_up` 에서 번 걸 `z_down` 에서 쓴다. `z_down` 이 늘어난
이유는 미확정인데, 하강 시작 시 브레이크가 아직 안 잠긴 상태라 **충돌 기준선
평탄 판정**이 더 걸린 것으로 보인다 (기준선 확정 시간이 0.36~1.31초로 흔들린다).

## 2. XY 축 — 속도 포화

300mm 이동을 속도별로 재고, 모터 위치로 **시작지연과 이동구간을 분리**했다.

```
속도   전체     시작지연   이동구간   실측속도
 80   4.78초    0.10초     4.46초    67.3mm/s
160   3.95초    0.21초     3.38초    88.8mm/s
250   4.11초    0.39초     3.42초    87.7mm/s      ← 더 안 빨라진다
```

**실측 속도가 ~88mm/s 에서 포화한다.** 명령을 160 으로 주든 250 으로 주든 같다.

원인이 아닌 것으로 확인된 것:
- `max_speed_dps 700` — X 는 88mm/s 에 303dps 면 된다 (여유 2배 이상)
- 가속 한계 — `accel_dpss_x/y 12000` 이면 0→88mm/s 가 0.03초
- 브레이크 대기 — 분리해서 쟀다 (0.1~0.4초)

**남은 후보: 모터 ROM 의 속도 제한, 또는 명령 단위 환산 배율.**
`_speed_for()` 는 `mm_s / mm_per_deg` 를 "모터축 dps" 라 부르는데,
`mm_per_deg` 가 출력축 기준이면 감속비만큼 어긋난다. **다음에 여기부터 볼 것.**

### 전류 (정격 6.1A rms, `axes.yaml` 설정 rated 7.8 / warning 9.0 / danger 12.0A)

```
 80mm/s   X 최대 2.56A   Y 최대 2.89A
120mm/s   X 최대 2.77A   Y 최대 2.90A
160mm/s   X 최대 2.58A   Y 최대 3.20A
250mm/s   X 최대 2.49A   Y 최대 3.11A
```

**속도를 3배 올려도 전류가 거의 안 는다** — 포화하고 있으니 당연하다.
정격의 절반 이하라 안전 여유는 충분하다. (X 는 X4-36, Y·Z·yaw 는 X4-10/12.5)

### 시도 ② XY 80 → 160mm/s — **채택**

실제 결속 회차로 비교:

| | 80mm/s | 160mm/s |
|---|---|---|
| 자세 유지 점 | 9.00초 | **8.55초** (−0.45) |
| 자세 변경 점 | 10.05초 | 10.05초 (±0) |
| 4점 회차 전체 | 45.3초 | 44.7초 |

결속 중 XY 이동은 100~200mm 로 짧아 효과가 300mm 시험보다 작다.
**전류 비용이 없으므로 유지한다.** `teleop.launch.py` 에 반영했다.

## 4. 다음에 팔 곳 (크기 순)

1. **XY 88mm/s 포화 원인** — 풀면 XY 이동 2.65 → ~1.3초, **점당 1.3초**.
   오늘 시도한 어떤 것보다 크다. `_speed_for()` 의 단위 환산과 모터 ROM
   속도 제한부터 볼 것.
2. **충돌 기준선 확정 시간** — 0.36~1.31초로 3배 흔들린다. `z_down` 안에
   들어가 있어 시간도 먹고, **기준선이 낮게 잡힌 회차에서 오감지가 난다**
   (0.43A 기준선 → −48.7mm 에서 멈춤 / 0.74A 기준선 → 같은 자리 통과).
   기준선에 하한을 두거나 평탄 판정을 안정화하면 **시간과 신뢰성을 같이** 얻는다.
3. **Z 속도** — 올리려면 `max_speed_dps` 도 같이 올려야 한다. 상승 전류가
   1.92A 라 여유는 있지만 중력 축이라 조심스럽다. 기대 이득 ~0.5초.
4. **`fire` 1.25초** — 결속건 기계 시간이라 소프트웨어로는 못 줄인다.

## 5. 측정 방법 메모 (다시 할 때)

- **점유 시간은 타임라인으로** 본다. 단계별 중앙값 합은 틀린다.
- **속도는 모터 위치 토픽(`/motor_0x14X_position`, 12Hz)으로** 잰다.
  `/stage/status` 는 2Hz 라 속도 미분이 노이즈다.
- **전류 토픽은 정지 중에 발행되지 않는다** (이동 중에만 ~7Hz).
  정지 전류를 보려면 다른 수단이 필요하다.
- 속도 시험은 **이동을 연달아** 해야 한다. 사이를 띄우면 브레이크가
  유예 뒤 잠겨서 재해제 대기가 매번 섞인다.

## 6. 추가 실측 — 가속이 진짜 병목이었다 (같은 날 저녁)

위 "88mm/s 포화" 는 **가속 제한**이었다. 사용자가 짚었고, 계산이 맞아떨어진다:

```
X 출력축 가속 = 12000 dps/s ÷ 36(감속비) × 0.2906 mm/deg ≈ 97 mm/s²
300mm 를 삼각 프로파일로 가면  평균 = √(a·d)/2 = √(97×300)/2 = 85.5 mm/s
                                                  ↑ 실측 82.7~85.9
```

**명령 속도에 애초에 도달하지 못한다.** 160 을 주든 250 을 주든 같은 이유다.

### ⚠⚠ 함정 — 가속은 런타임 파라미터로 안 바뀐다

`accel_dpss_x` 를 12000→36000 으로 바꿔가며 쟀는데 **전부 같은 값**이 나왔다.
원인: `stage_node._apply_accel()` 이 기동 4초 뒤 **한 번만** 돌고 타이머를
스스로 끈다. 파라미터를 바꿔도 모터(0x43)에 안 내려간다.

하마터면 "가속도 원인이 아니다" 로 잘못 결론 낼 뻔했다. 시험하려면:

```bash
ros2 topic pub --once /motor_accel std_msgs/String "{data: '0x145 40000'}"
```

### XY 가속 실측 (300mm, `/motor_accel` 로 직접 적용)

| 가감속 | 이동구간 | 평균속도 | X최대 | Y최대 |
|---|---|---|---|---|
| 12000 | 3.45초 | 86.9mm/s | 2.62A | 2.82A |
| 24000 | 2.71초 | 110.4mm/s | 2.95A | 3.00A |
| **40000** | **2.45초** | **122.7mm/s** | 2.67A | 3.26A |
| 60000 | 2.29초 | 131.5mm/s | 2.75A | 3.82A |

**40000 채택.** 60000 은 이득 0.16초에 Y 전류가 3.82A 로 뛴다.

### 결속 실측 (가감속 40000 적용)

```
4/4 완주 39.4초 (12000 일 때 44.7초)
자세 유지 점  8.55 → 8.10초
자세 변경 점 10.05 → 9.90초

전류 (정격 6.1A 대비)
  X 0x145  중앙 1.75A  p95 2.51A  최대 2.99A  (49%)
  Y 0x146  중앙 2.20A  p95 3.04A  최대 3.22A  (53%)
  Z 0x147  중앙 0.81A  p95 1.65A  최대 2.09A  (34%)

단계별 최대
  X: move_xy 2.99 · rotate 2.35 · retract 2.34
  Y: rotate 3.22 · retract 3.11 · move_xy 3.02   ← 가속 구간이 아니다
  Z: z_up 2.09 · done 1.34 · move_xy 1.05
```

**가속을 3.3배 올렸는데 전류는 거의 안 늘었다.** 가장 큰 Y 3.22A 도 가속이
아니라 yaw 회전 중 Y 가 버티는 몫이다.

## 7. Z 는 올리지 않는다 — 충돌 감지가 무력화된다

Z 가속은 올려도 거의 안 변한다 (이동 90mm 라 가속 구간이 금방 끝난다):

```
가감속 20000  하강 1.90초/47.5mm/s   상승 1.81초/49.7mm/s/1.88A
       40000  하강 1.84초/49.1mm/s   상승 1.61초/56.1mm/s/2.29A
       60000  하강 1.57초/57.5mm/s   상승 1.77초/50.9mm/s/2.04A
```

Z 는 **속도가 병목**이다 (`60mm/s ÷ 0.0906 = 662dps`, 상한 700 바로 아래).
속도와 `max_speed_dps` 를 같이 올리면 크게 빨라진다:

```
속도/상한      하강        상승        Z 최대전류
 60 /  700   1.55초      1.77초       2.12A
 90 / 1100   1.15초      1.14초       2.54A
150 / 1900   0.90초      0.91초       2.35A     ← 점당 ~1.5초 단축
```

### ⚠⚠ 그런데 올리면 안 된다

`collide_grace_max_sec = 1.5` 동안 충돌 감지가 **기준선을 잡느라 눈을 감는다.**
실측 확정 시간은 **0.30~1.11초** (중앙 0.50).

```
현재 60mm/s   z_down 1.55초 → 약 1.0초가 보호된다
150mm/s       z_down 0.90초 → 기준선이 1.11초 걸린 회차에서는
                              **무장 전에 하강이 끝난다** = 보호 0
```

### 두 문제가 한 자리에서 만난다

- 기준선이 **낮게** 잡히면 → **오감지** (0.43A 기준선에서 -48.7mm 에 멈춤.
  같은 자리를 0.74A 기준선으로 다시 하니 -97.4mm 까지 통과)
- 기준선이 **느리게** 잡히면 → 무장 전에 하강 종료 → **Z 속도를 못 올린다**

**기준선 확정을 안정화하면 신뢰성과 속도를 같이 얻는다. 다음 작업 1순위.**
