# 자율결속 알고리즘 — 2차년도 구현 현황과 3차년도 개편

작성 2026-10-17. 설계 상세는 [AUTONOMY_COVERAGE_DESIGN.md](AUTONOMY_COVERAGE_DESIGN.md),
그림은 [figures/](figures/).

세 가지를 다룬다 — ① 2차년도가 어디까지 구현돼 있나 ② 3차년도에 무엇을 새로
넣나 ③ 왜 강화학습 모델 대신 탐욕(greedy) 플래너를 쓰나.

## 1. 2차년도 자율결속 — 구현 현황

### 1.1 구조

자율주행이 두 갈래로 나뉘어 있다.

```
[A] UI 웨이포인트 ─▶ navigator ─▶ rebar_controller ──┐
[B] 배근인지 자율 ─▶ rebar_drive_node ───────────────┴─▶ /cmd_vel ─▶ drive_controller
                        ▲                                              ▲
                        └─ /deck_edge_status ── deck_edge_node ── /deck_edge_block
```

[A]는 좌표를 미리 아는 경로주행이고, **[B]가 자율작업 본체**다 — 좌표를 모른 채
보이는 배근을 따라가는 반응형. 둘이 `/cmd_vel` 을 공유하므로 소유권 규약이
명시돼 있다: A에 우선권, B는 A가 주행 중이면 시작 거부하고 주행 중 양보한다.

### 1.2 동작 — `rebar_drive_node` (1,777줄)

```
IDLE ─S23─▶ FWD_DETECT ⇄ FWD_STEP ─(배근끝)─▶ FWD_SETTLE
      ─▶ REV_DETECT ⇄ REV_STEP ─(배근끝)─▶ REV_SETTLE ─▶ DONE
```

한 사이클은 **정지 → 검출 → 결속 → 다음 거리 계산 → 이동 → 반복**이다.
위치추정도 경로추종도 없다. 매 정차마다 다시 보기 때문이다.

| 요소 | 내용 |
|---|---|
| 검출 | 워커 스레드 (제어 타이머에서 돌렸더니 executor 가 2.64초 막혔다) |
| 이동 | 엔코더 폐루프. odom 끊기면 중단 |
| 결속 | `/mission/command` 로 `TYING_START` + 좌표 전달, `TYING_COMPLETE` 대기 |
| 거리 계산 | `coverage_planner` (ROS 무관 순수함수) |

**이동거리 규칙**이 핵심이다. 교차점을 X로 묶어 열, Y로 묶어 행을 만들고,
인접 간격의 중앙값이 피치다. 결측 열 때문에 2×·3× 간격이 섞이면 최소간격의
정수배로 정규화해 복원한다. 이동거리는 `열수 × 피치` 가 **아니라**:

```
d = (마지막 결속 열 X) − (도달범위 시작) + 마진
```

열수×피치는 첫 열이 도달범위 시작에 딱 있을 때만 맞다. 2026-08-06 실측에서
313.8mm 를 지령했는데 유효 하한보다 2.2mm 커서 도달오차에 먹혀 **같은 열을 두 번
결속**했다.

### 1.3 배근 끝 판정 — `deck_edge_node`

무한궤도가 **철근 위를 밟고** 달리므로 주행가능 = 배근이 이어진 곳뿐이다.
세그멘테이션으로 `rebar_frac` 을 내서 ≥0.55 GO / <0.55 SLOW / <0.45 STOP.

설계상 중요한 두 가지:

- 미션 흐름과 **대화하지 않는다.** `drive_controller` 직전에 **방향별** 차단만
  건다. `/obstacle_pause` 를 재사용하지 않은 이유가 적혀 있다 — 그건 전 방향을
  래치해서 멈춘 뒤 후진 탈출까지 막아 로봇이 갇힌다.
- 전·후방을 **교대로** 추론한다. 진행방향만 보면 반대방향 판정이 stale 이 되어
  탈출 방향까지 차단된다.

### 1.4 실제 운용 설정

| 항목 | 값 | 비고 |
|---|---|---|
| 횡이동 | **비활성** | 모터 여유 부족으로 잠정 중단 (2026-08-18) |
| 레인 전환 상한 | 4 | 주행 테스트용 설정 |
| 결속 밀도 | `tie_every_n` | 주행방향으로 한 줄씩 건너뛰기 |
| 이중결속 방지 | `merge_policy=prefer_tie` + 좌표 이력 | |

### 1.5 실주행으로 얻은 안전 규칙 — **그대로 가져온다**

| 규칙 | 무슨 일이 있었나 |
|---|---|
| 결속 대기를 데크끝 판정보다 **먼저** 본다 | 2026-09-15 사고. 순서가 반대라 결속 대기 중 STOP 이 확정되자 대기를 버리고 횡이동으로 빠졌다 → **상부가 Z하강·트리거 하는 동안 하부가 기체를 들어 옆으로 옮겼다** |
| STOP 은 연속 3프레임 + 전환 직전 재확인 | 기둥을 지날 때 같은 초에 GO→STOP→GO. 한 프레임만 보고 **레인 하나를 통째로 건너뛰었다** |
| 횡이동은 1회전씩 쪼개고 매 회전 재판정 | 일괄 지령하면 2회째에 배근이 끊겨도 못 멈춘다 |
| 횡이동 부호를 눈으로 확인 | `left` 지령에 우측으로 갔다. 재판정이 보는 쪽과 가는 쪽이 반대가 되어 안전장치가 무력화 |
| 범퍼 차단 시간은 타임아웃에서 뺀다 | 안 빼면 범퍼를 누른 것만으로 타임아웃 |
| 상태 전이를 fsync 로 남긴다 | 프리즈 때 어느 상태였는지 몰랐다 |

### 1.6 구조적 한계 — **지도가 없다**

아는 것이 "지금 이 방향으로 더 갈 수 있나" 하나뿐이다. 그래서 두 가지가
구조적으로 불가능하다.

1. **중간에 막힌 자리를 건너뛰고 나중에 돌아오기.** 막힌 칸과 배근 끝을
   구별하지 못해 레인 중간이 막히면 나머지를 통째로 버린다.
2. **미결속 지점 추적.** 결속 이력은 "다시 쏘지 않기 위한 제외 목록"이지
   "아직 안 한 곳" 목록이 아니다.

덧붙여 레인 전환은 **멈춰 선 그 자리에서만** 일어난다. 물러났다가 다른 자리에서
비킨다는 선택지가 구조에 없다.

## 2. 3차년도 — 새로 넣는 것

### 2.1 핵심 결정 두 가지

**① 자유격자를 깔지 않는다. 철근 교차점 자체가 셀이다.**
매 정차마다 다시 보므로 누적 오차를 관측이 잡고(배근이 주기적이라 오차가 1피치
안에 묶인다), 셀 상태가 곧 미결속 목록이 된다.

**② 지도는 교차점 단위, 계획은 정차지 단위.**
한 번 서면 여러 점을 묶으니 점마다 계획할 이유가 없다. 후보 정차지는 **미결속
셀에서 역으로** 만든다 — 작업영역 크기를 미리 몰라도 성립한다.

### 2.2 모듈 — 질문이 다르면 나눈다

| 모듈 | 답하는 질문 |
|---|---|
| `coverage_reach` | 그 점을 **어느 자세로** 닿나 (캘리 모델 + 가동범위) |
| `coverage_space` | 로봇이 **거기 있을 수 있나** (몸체 + 장애물 사각, 통로 통과) |
| `coverage_map` | 여기서 **묶을 수 있나** (격자·셀 상태·플래너) |

처음엔 결속영역을 점유영역으로 썼는데, 그러면 장애물이 **작업 범위에 들어오기만
해도** 못 서는 것이 되어 지나치게 엄했다. 막는 것은 몸체이고, 결속영역은
"거기서 일할 수 있나" 일 뿐이다.

### 2.3 실측 전제

| 항목 | 값 | 출처 |
|---|---|---|
| 결속 가능 영역 | **520 × 380mm** · 0.197 m² · 충전율 98% | 캘리 모델 × 가동범위 계산 |
| 스테이지 스트로크 | X 453.7 · Y 349.1 · Z 139.2mm | `axes.yaml` |
| 장비 몸체 | **940(폭) × 1160(길이) mm**, 중심축 결속영역과 일치 | 실측 |
| 횡이동 | 1회전 = **50mm**, 50 dps (7.2초) | 실측 |
| 통과 최소 틈 | 횡 **1060** · 종 **1280mm** | 위에서 유도 |

⚠ 결속 영역을 **460 × 370mm** 로 적은 자료가 있으면 그건 카메라 좌표다.
카메라가 철근 평면에 29° 기울어 cam_y 가 단축돼 보인다 (460 / cos29° = 526).

### 2.4 새로 되는 것

| | 2차년도 | 3차년도 |
|---|---|---|
| 막힌 자리 | 배근 끝으로 오인, 레인 포기 | **건너뛰고 나중에 돌아온다** |
| 레인 전환 | 멈춘 자리에서만 | **물러났다가 다른 자리에서** |
| 통로 | "장애물 있다/없다" | **지나갈 수 있나** (몸체 사각 vs 장애물 사각) |
| 돌아가기 | 없음 | **경로탐색**(A\*) — 틈으로 들어갔다 나온다 |
| 미결속 보고 | "미결속" 한 덩어리 | **도달 불가 / 격자 위상 / 미처리** 로 구분 |

마지막 항목이 운용에서 중요하다. 전부 "미결속"으로 뭉뚱그리면 **버그인지 물리적
한계인지** 알 수 없다.

- **도달 불가** — 그 셀을 덮는 어떤 자리에도 몸체가 안 들어간다 (기둥 옆)
- **격자 위상** — 설 자리는 있는데 횡이동 50mm 격자에 안 맞는다
- **미처리** — 갈 수 있는데 계획이 멈췄다 = **진짜 결함**

### 2.5 측정 결과

2.8 × 2.0m 데크 · 배근 200mm · 기둥 300mm · **기둥 위치 18가지**.
양쪽에 같은 몸체 제약을 적용했다.

| | 결속 점수 (165점 만점) | 정차 |
|---|---|---|
| 2차년도 | **30 ~ 123** (평균 79) | 7 ~ 35회 |
| 3차년도 | **140 ~ 145** (평균 141) | 29 ~ 31회 |

**2차년도는 기둥이 어디 있느냐에 따라 4배 넘게 흔들린다.** 레인 전환을 하필
기둥 자리에서 시도하면 거기서 작업이 끝나기 때문이다. 3차년도는 기둥 위치와
거의 무관하게 140 선을 유지한다 — 못 묶는 점은 **기둥 옆 도달 불가**뿐이다.

장애물이 없는 판(7×5, 피치 200mm)에서는 **정차 9회로 35점 전부**를 묶는다.
7열을 3열씩 3묶음 × 5행을 2행씩 3묶음 = 9 로, **기하학적 최소**다.

### 2.6 기둥 하나의 대가

기둥 300 × 300mm 가 **1.58m × 1.36m** 를 사용 불가로 만든다 — 자기 면적의 약
25배다. 몸체(940 × 1160)가 기둥에서 절반+여유만큼 떨어져야 하기 때문이고,
"장애물이 있다/없다" 판정으로는 나오지 않는 숫자다. 현장 배치를 볼 때 기둥
주변 1.6m 는 수작업 구역으로 잡는 편이 현실적이다.

### 2.7 구현 단계 — **카메라를 기다리지 않아도 된다**

| 단계 | 내용 | 장비 |
|---|---|---|
| 1~2 | 지도·플래너 모듈 + 시뮬 | **없음** (완료) |
| 3 | 비용 상수 실측 | 결속 1사이클 |
| 4 | dry-run — 실제 검출을 먹여 계획만 출력 | 정차 상태 |
| 5~6 | 한 레인 자율 → 횡이동 포함 | 주행 |
| 7 | deck_edge 연동 | **ZED X 필요** |

전후방 카메라가 하는 일은 "데크 밖으로 떨어지지 않기"(안전)다. "어디까지
작업할지"는 교차점 검출기가 이미 답한다 — 앞에 미결속 점이 없으면 거기가
끝이다. 그래서 1~6단계는 지금 할 수 있고, 6단계까지는 사람이 보는 앞에서 돌린다.

## 3. 왜 탐욕 기반인가 — 강화학습 모델과의 비교

8차 학습 PPO(CNN) 모델을 받아 검증하고 같은 판에서 비교했다.
모델 자체는 정상이다 — 인수인계 문서의 **10개 테스트 그리드를 10/10 재현**했다.

### 3.1 결과

같은 격자·장애물·시작점·비용모델. RL 의 한 칸씩 이동은 **실제 로봇 동작으로
환산**했다 (묶을 필요 없는 칸은 안 멈추고 통과).

| 판 | RL 이동시간 | 탐욕 이동시간 |
|---|---|---|
| 3×3 | 239 s | **190 s** |
| 4×5 | 511 s | **359 s** |
| 4×5 + 장애물 1 | 551 s | **487 s** |
| 5×8 | 931 s | **626 s** |
| 5×8 + 장애물 2 | 5,119 s | **740 s** |
| 6×10 + 장애물 3 | 1,521 s | **1,207 s** |
| **합계** | **9,118 s** · 횡이동 1,032회 | **3,790 s** · 횡이동 **248회** |

커버리지는 둘 다 100%. **전 판에서 탐욕이 이긴다 — 합계 2.4배.**

### 3.2 이유 ① 횡이동 가격이 안 맞는다 (가장 큼)

모델은 Y 이동 비용을 X 의 **4배**로 학습했다. 3차년도 실제는 **약 6배**다 —
Y 400mm = 8회전 × 7.2초 = 61.6초 vs X 550mm ≈ 10초. 저평가된 만큼 횡이동을
남발하고, 그것이 시간 차이의 거의 전부다 (1,032회 vs 248회).

이건 우리 측정만의 주장이 아니다. 인수인계 문서 스스로 횡이동 비율(YR) 평균
**0.34**, 목표 0.25 미달로 보고하고 있고, `5×8+장애물2` 의 "PE 2.62 왕복 배회"
사례도 적어 두었다. 우리가 측정한 664회전이 바로 그 현상이다.

### 3.3 이유 ② 문제 구조가 스윕이라 전역 최적화 여지가 작다

커버리지는 "거의 직사각형 격자를 빠짐없이 훑기"다. 레인을 끝까지 쓰고 한 번만
비키는 것이 최적이고, **비용이 제대로 들어간 탐욕이 그걸 바로 찾는다.**
장애물 없는 7×5 에서 탐욕은 정차 9회 = 기하학적 최소를 낸다. 더 줄일 수 없으니
전역 최적화로 벌 것이 없다.

흥미로운 점 하나 — 레인 유지 선호 계수를 두고 0~1 로 쓸어 봤더니 **거의 영향이
없었다.** 후보 자세를 격자 위에서 전부 열거하도록 고친 뒤로는, 따로 유도하지
않아도 비용 구조만으로 레인을 유지한다.

### 3.4 이유 ③ RL 은 지도를 미리 알아야 한다

모델은 `reset(rows, cols, obstacles, start=(0,0))` 로 **작업영역과 장애물을
미리 받는다.** 우리 상황은 돌아다니며 알아가는 것이다. 즉 비교 자체가 RL 에
유리한 조건이었고, **그 핸디캡을 주고도 졌다.**

그 밖의 제약: 학습 범위는 행 2~6 · 열 2~15, 시작점은 항상 (0,0), 32×32 초과
격자는 사용 불가, 경로에 재방문이 섞여 상위 제어기가 "첫 방문에서만 결속"을
처리해야 한다. 대형 격자(10×15)는 `max_steps` 에서 잘려 완료율 0.986이다.

### 3.5 칸 크기도 다시 잡아야 한다

모델은 칸을 **X 600 · Y 400mm** 로 가정한다. 실제 도달 범위는 520 × 380mm 라,
600mm 로 쓰면 칸마다 **80mm 가 손에 안 닿아** 결속 안 된 띠가 규칙적으로 남는다.
Y 400mm 도 2차년도 기준(44mm/회전 × 9)이고 3차년도는 50mm/회전이다.

### 3.6 그래서 — 지금은 붙이지 않는다

다시 검토할 조건은 둘이다.

1. **실제 비용비(6:1)와 50mm 양자화로 재학습** — Y 이동 비용 −2.0 → −3.0 수준,
   칸 크기 X 440 · Y 350mm (결속영역보다 작아야 띠가 안 생긴다)
2. **탐욕이 실제로 지는 배치를 찾는 것** — 비교 도구(`tools/test/coverage_vs_rl.py`)를
   남겨 두었다. 판만 추가하면 된다

지금 당장 쓸모 있는 것은 모델이 아니라 **그 환경**이다. 10개 테스트 그리드가
우리 플래너의 회귀 테스트가 된다.

> 참고: `gymnasium` 은 설치하지 않았다. `gym.Env` 상속과 `spaces` 선언에만
> 쓰므로 20줄 shim 으로 충분하고, 설치하면 numpy 가 2.x 로 올라가 JetPack
> OpenCV 와 cv_bridge 가 죽는다.

## 4. 한계와 남은 일

### 4.1 지금 가정인 것

| 항목 | 상태 |
|---|---|
| 비용 상수 (주행 70mm/s · 횡 7.2s/회전 · 결속 1점 0s) | **실측 전 임시값** |
| 장애물 크기 | 시뮬이 알려준다. 실제로는 전후방 ZED X 의 깊이가 필요하다 |
| 2차년도 비교 | 코드를 **읽어 옮긴 재현**이다. 2차년도를 실제로 돌린 것이 아니다 |

마지막 항목은 특히 조심할 것. 이 재현을 만들면서 **여섯 번 고쳤고**, 그중
다섯 번은 2차년도를 부당하게 깎던 쪽, 한 번은 봐주던 쪽이었다. 매번 결과를
보고서야 알았다.

### 4.2 막혀 있는 것

- **전후방 ZED X 두 대가 GMSL 링크를 못 잡는다.** 드라이버·SDK·래퍼는 전부
  정상이고 디시리얼라이저도 기동하는데 카메라가 안 보인다. 캡처카드 배럴잭
  전원(9~19V)과 FAKRA 체결 확인에서 멈춰 있다.
- 결속 사이클 비용 미실측
- 재시도 정책 — 충돌로 실패한 자리는 좌표가 틀린 것이므로 같은 좌표로
  재시도해도 소용없다. 카메라 폐루프 보정과 함께 정해야 한다

### 4.3 알아둘 제약

**격자 위상.** 횡이동이 1회전 = 50mm 로 양자화돼 있어, 장애물이 가능 구간을
50mm 보다 좁게 잘라 놓으면 몇 mm 차이로 못 간다. 결속영역 V 폭이 380mm 라
평소엔 선택지가 7개쯤 되어 문제가 없지만, 좁은 판에서는 걸린다.
기구가 1회전 50mm 고정이라 완화할 방법이 없으니 **아는 채로 운용**한다.
