## 0. 기동 전 확인 (전원을 내렸다면)

```bash
ros2 topic echo /homing_status --once --field data     # refs 가 {} 면 호밍부터
ros2 topic pub --once /homing_cmd std_msgs/String '{data: all}'   # 약 70초
```

호밍 기준값은 `homing_node` 메모리에만 있어 **전원 재투입·서비스 재시작으로
날아간다.** `refs` 가 비어 있으면 mm 이동이 전부 거부된다.
오늘 마감 시점 값: `z 287.5 · x -384.0 · yaw -121.9 · y -343.0`

⚠ **`navigator` 의 `path_file` 을 내가 비워 뒀다.** 자율 주행 고리가 미션
파라미터를 쓰려면 그래야 한다. 데모 경로를 다시 돌리려면 되돌릴 것:

```bash
ros2 param set /navigator path_file \
  /home/koceti/ros2_ws/src/rebar_control/path_generation/test_path.txt
```

## 1. 자율 결속 한 주기 — 오늘 못 한 것 (최우선)

주행 한 걸음은 실장비로 **확인 완료**(목표 141mm → 실제 138.4mm). 그 다음이
남았다. 호밍이 끝나 있어야 한다 — 오늘 `tie` 가 "현재 X·Y mm 를 모른다" 로
거부당한 것이 그 이유였다.

```bash
ros2 run rmd_robot_control drive_autonomy_node --ros-args \
  -p dry_run:=false -p max_stops:=1 -p tie_at_stop:=true -p max_leg_mm:=250.0
ros2 topic pub --once /autonomy/cmd std_msgs/String '{data: start}'
```

⚠ 결속건이 실제로 내려오므로 **건 아래 철근 상태와 주변 간섭을 먼저 볼 것.**
⚠ 장비를 움직이는 단계다 — 사용자 확인을 받고 시작한다.

되면 `max_stops` 를 올려 여러 정차지로 넓힌다. 그때 비로소 "실제 데크에서
고리가 종료되는가" 가 증명된다 (드라이런은 장비가 안 움직여 같은 교차점을
계속 보므로 종료를 증명하지 못한다).

## 2. 층 필터 — 정답을 더 모아 임계 확인

`layer_ratio_min = 0.35` 는 **현재 설정으로는 한 장면**에서만 확인됐다
(진짜 0.416~0.482 / 허위 0.177~0.252, 여유 0.164). 앞선 세 장면은 ROI 를
분리하기 전 값이라 참고만 된다.

- 장비를 옮겨가며 2~3 장면 더 받아 임계를 굳힌다
  (`tools/test/` 의 캡처 스크립트로 번호 붙은 그림을 뽑아 사람에게 라벨을 받는다)
- **정답을 좌표가 아니라 프레임과 함께 저장할 것.** 오늘 장비가 움직여
  좌표 기준 정답표가 무효가 됐고, 측정 한 번을 통째로 버렸다.
- 출력으로 나간 4점이 정확히 무엇인지 아직 대조 안 했다 (진짜 3 + 가동범위
  밖 1 로 추정)

## 4. 전방 ZED 거리 — 좁은 틈 판단 전에 재확인

보정으로 depth 는 살렸다(채움률 52.6%→79.7%, 평면 잔차 7.6→2.2mm).
절대 거리는 **1.3m 에서 20mm 이내** 라는 상한만 안다. 통과 판단은 필요
여유 1060mm 에 마진 ±60mm 인데 1~2m 에서 오차가 15~30mm 라 넉넉하지 않다.
좁은 틈을 실제로 노리기 전에 한 번 더 잴 것.

`optional_opencv_calibration_file` 을 **열 때마다** 넘겨야 한다 — 빠뜨리면
경고 없이 깨진 공장값으로 돌아간다.
