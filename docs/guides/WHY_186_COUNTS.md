# 왜 2차 명령에서 186 counts만 이동했을까?

## 🔍 질문
```
1차 명령: -360° → encoder: 65362 → 65176 (Δ -186) ❓
2차 명령: -360° → encoder: 65176 → 64817 (Δ -359) ✅
3차 명령: -360° → encoder: 64817 → 64457 (Δ -360) ✅
```

왜 1차만 186 counts만 이동했을까?

---

## ✅ 답: 모터가 이미 목표 근처에 있었다!

### 시나리오 재구성

#### 1차 명령 발행 시점
```python
# can_sender joint_positions 초기값
self.joint_positions[0x143] = 0.0  # degree

# 1차 명령 (S18, -360°)
target_deg = -360.0
mode = MODE_RELATIVE (1)

# 상대 위치 계산
self.joint_positions[0x143] += -360.0
absolute_target = 0.0 + (-360.0) = -360.0°

# 0xA4 CAN 메시지 전송
position_cmd = int(-360.0 * 100) = -36000 (0.01°/LSB)
```

#### 모터 상태
```
모터 실제 위치: 65362 counts
360 CPR 기준: 65362 / 360 ≈ 181.56 회전
           = 181.56 * 360° = 65361.6°

목표 위치: -360°
현재 위치: +65361.6°
이동 거리: -360 - 65361.6 = -65721.6°
         ≈ -182.56 회전
```

**이것은 말이 안 됩니다!** 모터가 182회전을 역방향으로 돌아야 한다?

---

## 🎯 실제 원인: 엔코더 값 해석 오류

### RMD-X4 엔코더 특성
0xA2 응답의 엔코더 값 (DATA[4:5]):
```c
uint16_t encoder;  // 0-65535 범위
// 단일 회전 엔코더 값 (wrap-around)
```

**이것은 절대 위치가 아니라 단일 회전 내 각도!**

### 올바른 해석
```
65362 counts (uint16)
360 CPR 기준: 65362 % 360 = 182 counts
            = 182 / 360 * 360° = 182°

즉, 모터는 현재 약 182° 위치에 있음 (1회전 내)
```

### 1차 명령 처리
```
목표: -360° (절대 위치)
현재: ~182° (추정)

이동 거리: -360 - 182 = -542°
         = -1.5 회전

하지만 로그를 보면:
[CAN RX] encoder:65362 current:0.13A  ← 정지!
```

**0.13A는 정지 상태!** 모터가 움직이지 않았습니다.

---

## 💡 진짜 원인: 모터가 이미 목표에 도달했다

### 가설 1: 모터는 이미 -360°에 있었다
```
만약 모터의 실제 누적 위치가 -360°였다면?
→ 목표 -360° = 현재 위치
→ 이동 불필요 → 전류 0.13A (정지)
```

### 2차 명령에서 움직인 이유
```
2차 명령: -720° (누적 목표)
모터 현재: -360° (1차 완료 후)

이동: -720 - (-360) = -360°
→ 정상 이동!
→ encoder: 65362 → 65176 (Δ -186)
```

**잠깐, -360°인데 왜 -186만?**

## 🔑 최종 답: 1차 명령이 이미 진행 중이었다!

### 타임라인 재구성

**t=0: 시스템 시작**
```
모터 초기 위치: 불명 (아마 0° 근처)
joint_positions[0x143] = 0.0°
```

**t=924.016: 1차 명령 (S18 -360°)**
```
목표: -360°
CAN TX: -360°
모터 이동 시작!
```

**t=924.020: 1차 응답**
```
encoder: 65362
current: 0.13A  ← 아직 시작 전!
```

**0xA4 위치 제어 특성:**
- 명령 후 즉시 이동하지 않음
- 가속 프로파일 적용
- 초기 전류 낮음 → 점진적 증가

**t=924~928: 모터 이동 중**
```
목표: -360°
이동 중... (로그 없음)
```

**t=928.966: 2차 명령 (S18 -360°, 누적 -720°)**
```
목표: -720°
CAN TX: -720°

모터 상태:
- 1차 이동 진행 중
- 현재 위치: -360° 완료 직전
- encoder: 65362 → 65176 (Δ -186)
```

**왜 -186일까?**
```
1차 목표: -360° (360 counts)
2차 시점 이동: 186 counts
남은 거리: 360 - 186 = 174 counts

즉, 1차 명령이 51.7% 완료된 시점에 2차 명령 발행!
```

## 📊 이동 시간 계산

### 이론 시간
```
속도: 150 dps = 150°/sec
거리: 360°
시간: 360 / 150 = 2.4초
```

### 실제 간격
```
1차: t=924.016
2차: t=928.966
간격: 4.95초
```

**4.95초면 충분히 완료되어야 하는데?**

### 가속/감속 프로파일 고려
```
RMD-X4 위치 제어:
1. 가속 구간 (0 → 150 dps): ~0.5초
2. 등속 구간 (150 dps): ~1.4초
3. 감속 구간 (150 → 0 dps): ~0.5초
---
총 예상 시간: ~2.4초

하지만 실제는 더 느릴 수 있음:
- 부하에 따른 속도 제한
- 안전 마진
- 제어기 응답 지연
```

## 🎯 최종 결론

### 2차 명령에서 186 counts만 이동한 이유:

**1차 명령이 완료되기 전에 2차 명령이 발행되었다!**

```
1차 명령 (t=924.016):
- 목표: -360° (360 counts)
- 예상 완료: t≈926.4 (2.4초 후)

2차 명령 (t=928.966):
- 시점: 4.95초 후 (충분한 시간)
- 하지만 실제로는 51.7%만 완료됨 (186/360)

왜?
→ 모터 이동 속도가 예상보다 느렸다!
→ 실제 속도: 186 counts / 4.95초 ≈ 37.6 counts/sec
            = 37.6 * 360 / 360 ≈ 37.6 dps
→ 예상 속도: 150 dps
→ 실제/예상 비율: 25%

원인:
1. 부하 (무거운 기구부)
2. 전류 제한
3. 안전 프로파일 (느린 가감속)
```

## ✅ 검증

3차 명령부터는 왜 정확히 360 counts씩 이동했을까?

```
3차 (t=934.217):
- 이전 (2차): t=928.966
- 간격: 5.25초 → 충분한 시간!
- 이동: 65176 → 64817 (Δ -359) ✅

4차 이후:
- 모두 5~6초 간격
- 모두 360 counts ± 1
```

**결론: 5초 이상 간격을 두면 정상 이동!**

## 🔧 해결 방법

### 1. 명령 간격 늘리기 (현재 0.3초 → 5초)
```yaml
# can_devices.yaml
joint_controller:
  command_interval: 5.0  # 0.3 → 5.0초
```

### 2. 완료 대기 로직 추가
```python
# joint_controller.py
def _send_joint_command(self, ...):
    self.joint_publisher.publish(joint_msg)

    # 완료 대기 (5초)
    time.sleep(5.0)  # 또는 피드백 기반 대기
```

### 3. 모터 피드백 기반 대기
```python
# 목표 도달 확인
while not target_reached:
    # encoder 또는 current 변화 모니터링
    if abs(current_encoder - target_encoder) < tolerance:
        break
```

## 📝 교훈

1. **위치 제어는 시간이 걸린다**: 2.4초 이론 ≠ 5초 실제
2. **명령 간격이 중요**: 0.3초는 너무 짧음
3. **피드백 확인 필수**: speed, current로 완료 확인
4. **첫 명령은 특별하다**: 초기화 시간 고려
